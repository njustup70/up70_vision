## 0. 它是什么

UP70 视觉组的 2D 视觉链路：**判色（HSV）→ ArUco 检测 → 位姿 → 画图与落盘**。

画面从哪来三选一：

| 输入源 | 说明 | 什么时候用 |
|---|---|---|
| `synthetic` | 程序自己造图（色块 / ArUco），噪声与位置可控 | 开发算法、跑回归、没有素材时 |
| `replay` | 图片目录或视频文件 | 复盘现场素材、跑验收 |
| `camera` | 海康 MV-CU013-A0UC（MVS SDK，USB3 Vision） | 真机演示与调参 |

所有动作只有**一个入口**：`python -m up70_vision <子命令>`。

## 1. 三分钟起步

```bash
git clone <仓库地址> && cd up70_vision
docker compose -f .devcontainer/docker-compose.yml build   # 首次约 2~3 分钟
./demo.sh                                                  # 四步串起来，谁挂了报谁
```

`./demo.sh` 依次做四件事，失败会打出"第几步、哪条命令、退出码"：

1. 构建镜像
2. `python -m up70_vision doctor`（环境自检）
3. `python -m up70_vision demo`（OpenCV 冒烟）
4. `python -m up70_vision run`（跑一批合成图）

第二次跑用 `SKIP_BUILD=1 ./demo.sh` 跳过构建。

不想用 Docker（本机 Python 3.10 + OpenCV）：

```bash
pip install -e . && python -m up70_vision doctor
```

跑完应看到 `output/demo/` 里四样东西：

| 文件 | 是什么 |
|---|---|
| `frame_*.png` | 叠加图（框 + 颜色标签 + HUD） |
| `results.json` | 每帧每个检出物的结构化结果 |
| `detections.csv` | 平铺表，方便直接拖进 Excel 或脚本 |
| `summary.json` | 汇总（帧数、颜色分布、命中率、真值比对） |

终端最后一行是自检结论：合成图 3 帧 × 6 块 = **18 个色块，实得 18、判色 18/18 全对**，退出码 0。

## 2. 一个入口：14 个子命令 + `clean`

不带参数敲 `python -m up70_vision` 就是这张表。按"你想干什么"分组：

| 想干什么 | 命令 |
|---|---|
| 跑一批图，出结果 | `run`（批处理：全部读完再汇总） |
| 盯着看实时画面 | `live`（ArUco 专用：逐帧检测 + 窗口/落盘） |
| 确认环境没坏 | `doctor`（环境自检）、`demo`（OpenCV 冒烟） |
| 验证检测/位姿准不准 | `check-aruco`（ID/四角/中心）、`pose-check --dir`（逐图）、`pose-check --sweep`（批量扫描，出 CSV + MD + 8 张曲线） |
| 造素材 | `gen-aruco`、`gen-scenes`、`gen-chessboard` |
| 标定相机 | `calibrate` |
| 调颜色 / 看相机原始判色 | `hsv-tuner`（需 GUI）、`mvs-color`（需 MVS SDK） |
| 导出模型 / 构建文档 | `export-yolo`、`gen-html` |
| 清理 | `clean`（清 `output/` 与所有 `__pycache__/`） |

每个子命令的参数照旧：`python -m up70_vision run --help`。

## 3. 调参只改两个文件

| 文件 | 放什么 | 什么时候动 |
|---|---|---|
| `configs/color_thresholds.yaml` | 颜色 HSV 范围 **+ 判色门槛**（饱和度/亮度下限、命中率、边框裁剪、最少有效像素） | 换场地、换光照。**调颜色只开这一个文件** |
| `configs/default.yaml` | 输入源、相机曝光与增益、检测器、输出、日志等级 | 换跑法（合成 → 回放 → 相机） |

常用开关：

```bash
--set color.hit_ratio_min=0.6      # 临时盖掉阈值表里的门槛（不改文件）
--dump-config                      # 打印这次真正生效的配置后退出
--no-output --limit 3              # 不落盘，只看汇总
```

规则：`--set` **只能改已存在的字段**，名字写错启动即报错（退出码 2），不会静默忽略。

调颜色的正确姿势（需要 GUI）：

```bash
python -m up70_vision hsv-tuner --image data/clips/sample.jpg --colors red
```

拖滑条看中间那幅叠加图，目标颜色被覆盖、背景干净就对了；回车写回阈值表（注释保留）。

> 别对着代码猜数字：`min_saturation`（什么算**有效像素**，命中率的分母）与每个颜色段里的
> `s_lo`（什么算**这个颜色**，分子）是两个东西。改错一个不报错，只会让命中率悄悄偏低。

## 4. 接真相机（三步，缺一步打不开）

海康 MV-CU013-A0UC 走 **USB3 Vision（GenICam），不是 UVC**：宿主机没有 `/dev/video*`，
`cv2.VideoCapture` 打不开它，报错也不会说明原因。

1. **宿主机 udev 给权限**：`/etc/udev/rules.d/99-hikrobot.rules` 写
   `SUBSYSTEM=="usb", ATTRS{idVendor}=="2bdf", MODE="0666", SYMLINK+="hik_camera"`，
   然后 `sudo udevadm control --reload-rules && sudo udevadm trigger`，再拔插相机。
2. **MVS 的 deb 放进 `.devcontainer/pkgs/`**，重新 `build` 镜像（deb 写不进 `pyproject.toml`）。
3. **compose 已透传 `/dev/bus/usb`**。相机是**独占资源**：MVS 客户端、调参窗口、本仓库三者互斥。

```bash
xhost +local:root
docker compose -f .devcontainer/docker-compose.yml run --rm \
  -e DISPLAY=$DISPLAY -v /tmp/.X11-unix:/tmp/.X11-unix up70-vision \
  python -m up70_vision live --set detector.name=aruco --set input.source=camera \
  --set input.camera.exposure_us=40000 --set input.camera.gain_db=15
```

窗口里按 `q` / `ESC` 退出。曝光按场地重调：20 ms 太暗（灰度均值 20）、80 ms 时手举码会拖影
（曝光期内移动约 20 px ≈ 一个格子），**动目标用 40 ms**。

## 5. 加位姿：只多两个参数

```bash
--set pose.enabled=true --set pose.marker_size_mm=82.5
```

- `pose.marker_size_mm` 必须**卡尺量黑框外沿**（不含白边）。填错不会让重投影误差变大，
  只让距离按比例错。
- 终端每 0.5 s 一行，**码增减或 ID 变化立即补一行**，无码也打 `markers=0`：

```text
t=0.03s | frames=1 | fps=48.2 | markers=1 | id=0 center=(642.3, 532.5) d=317mm tilt=37.6 yaw=-144.0
```

| 字段 | 含义 |
|---|---|
| `d` | 斜距（毫米） |
| `tilt` | 码面与光轴夹角（0 = 正对） |
| `yaw` | 面内转角 |

- **正视附近 `tilt` 不可信**：0° 附近弱可观（实测可散到 10°+），倾斜 15° 以上才降到 1° 内。
- 没有内参时位姿自动关闭并打警告（`calibration.required=false`）；设 `true` 则直接失败，
  避免"以为在算位姿其实没算"。
- 没有显示器就加 `--headless --save-every 30 --limit 300`，叠加图落在 `output/aruco/`。

## 6. 标定（换相机或换分辨率才做）

```bash
# 1) 出棋盘：PNG + PDF，打印时选「实际大小」
python -m up70_vision gen-chessboard --cols 9 --rows 6 --square-mm 15

# 2) 现场采 15 张并解算，结果写 configs/camera_calibration.yaml
python -m up70_vision calibrate --capture 15 --board 9x6 --square-mm 23
```

两个尺寸别混（都"不报错只让数字错"）：

| 尺寸 | 值 | 用在哪 |
|---|---|---|
| 棋盘格方格边长 | 23 mm（实量，标称 15） | 标定 `--square-mm` |
| ArUco 码边长 | 82.5 mm | 位姿 `pose.marker_size_mm` / `--marker-mm` |

仓库带了一份内参快照（2026-10-19，33 视图，RMS 0.473 px，1280×1024，fx≈1321.67），
新 clone 直接能跑位姿；重标定会覆盖同一路径，提交前确认是不是全队约定的那台相机。

## 7. 代码在哪（已扁平化）

```text
src/up70_vision/
├── types.py color.py pipeline.py calibration.py pose.py     # 算法，全在包根
├── image_io.py logging.py                                   # 基础设施，也在包根
├── detectors/     blob / aruco / stub_aruco / yolo          # 一族可替换实现
├── config/        configs/*.yaml 的加载与校验
├── io/            camera（MVS）/ replay / synthetic
├── viz/           画框、坐标轴、HUD、落盘
├── cli/           parsers / run / live（唯一业务实现）
├── tools/         env aruco blob yolo calibration pose doc（按功能分组）
├── api.py         库调用门面：detect(image_bgr, "aruco")
└── __main__.py    统一入口
```

依赖方向是硬约束、单向：

```text
config ┐
       ├─> 根级算法模块 ─> io ─> viz ─> cli ─> __main__.py
image_io/logging ┘                          └─> api.py
```

算法模块（`types`/`color`/`pipeline`/`calibration`/`pose`/`detectors`）**不读文件、不开窗口、
不 import ROS**，所以能脱离硬件跑测试；`cli/` 与 `tools/` 不进 API/ROS 节点的 import 路径。

## 8. 自检与测试

```bash
python -m up70_vision doctor        # 环境（Python / opencv / 图像读写往返）
python -m up70_vision demo          # OpenCV 冒烟，末行 PASS
python -m up70_vision check-aruco   # 期望 9/9，中心 0.00 px，四角 ≤ 0.23 px
python -m up70_vision run           # 期望 18 个色块、18/18 判对
pytest tests/ -q                    # 103 passed
```

镜像里没装 pytest，所以 `tests/` 每个文件都能单独跑：`python tests/test_pose.py`。
断言必须带具体数字（`9/9`、`≤ 0.23 px`），不写 `assert x > 0`。

## 9. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 容器里 `live` 起不来，报 Qt / xcb | 没有 X server：加 `--headless --save-every 30 --limit 300` |
| Windows 终端打 ✅ 报 `UnicodeEncodeError` | 走统一入口 `python -m up70_vision ...`（入口内联了切 UTF-8 的逻辑）；直接 `python -m up70_vision.tools.xxx` 不会切 |
| 相机打不开 | MVS 客户端/调参窗口占着（独占）；deb 没进镜像；udev 没配；没透传 `/dev/bus/usb` |
| 位姿一直"解算失败" | 内参缺失或分辨率不匹配（会告警一次）；码边长填错（量到白边） |
| `output/` 越来越大 | `python -m up70_vision clean`（`output/`、`__pycache__/` 都是生成物，不进版本库） |
| 改了代码容器里没变 | 代码是 bind mount，立即生效；只有改 `pyproject.toml` 才需要重新 build |
| `git status` 一堆未跟踪文件 | 都是生成物：`output/`、`data/`、`docs/*.html`、模型权重、内参 YAML，已被 `.gitignore` 排除 |
| 想吐一轮干净状态 | `python -m up70_vision clean` 后目录回到"刚 clone 完"的样子 |
