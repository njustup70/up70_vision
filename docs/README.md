# docs 目录索引

`docs/` 里有十来份文档、二十多万字。这份索引只回答两件事：**先读哪篇**、**哪篇还能改**。

> 状态约定
> - **活文档**：跟着代码一起改。内容过期就是 bug（协作规范第 2、4 条）。
> - **存档**：只在查"当时那个数字是哪来的"时读，不要再往里加新内容。
> - **一次性**：某个阶段写完就定稿，之后不改。

---

## 第一次来，按这个顺序读

| # | 读什么 | 为什么先读它 |
|---|---|---|
| 1 | 仓库根的 `README.md` | 三条命令跑出第一张结果图；看完全文只需 5 分钟 |
| 2 | `docs/interface.md` | 唯一的契约来源（`Frame` / `Detection` / `ArucoMarker` / `MarkerPose`），改它要先改文档再改实现 |
| 3 | `docs/视觉组协作规范.md` | 怎么提交、怎么评审、AI 生成的代码要能解释（只有 6 条，5 分钟） |
| 4 | 按你要动的那一块选专业篇（见下表） | — |

调色阈值 / 接相机 / 改位姿算法之前，**先扫一遍 [`archive/pitfalls.md`](archive/pitfalls.md)**：
里面四十多个坑大多是"不报错但结果不对"，比报错难查得多。
