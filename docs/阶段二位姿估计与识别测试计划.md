## 二、任务 2（位姿估计）技术方案

### 2.1 数据流

```
图片/相机帧 image_bgr
  → ArucoDetector.detect()            → list[ArucoMarker]（corners_px 已是亚像素）
  → undistort_points(corners, K, D)   → 理想像素坐标（方案 B，不动原图）
  → estimate_pose(corners, L, K)      → MarkerPose（rvec, tvec, distance, tilt, yaw）
  → viz.draw_pose_axes / cli 终端行 / writer 落盘
```

### 2.2 数学口径（写死，避免两个人各算各的）

| 项 | 约定 |
|---|---|
| 码的三维模型 | 码中心为原点、码面 `z=0`。四个点按 **IPPE_SQUARE 硬性要求的字面顺序**给出，依次对应图像里的 TL、TR、BR、BL：`(-L/2, +L/2, 0), (+L/2, +L/2, 0), (+L/2, -L/2, 0), (-L/2, -L/2, 0)`。`L = marker_size_mm`，单位**毫米**。**顺序写错不报错，只给垃圾解（实测 RMS 5930 px）** |
| 码的 z 轴 | `R` 的第三列。**实测**（40 mm 码、200 px、正视）：解出 `R = diag(1, -1, -1)`，即码 x 轴≈图像 x 向右、码 y 轴指向码的**上边**、码 z 轴**指向相机**（码面外侧），`R[2,2] = -1.00` |
| 相机坐标系 | OpenCV 光学系：x 右、y 下、z 朝前（沿光轴） |
| `tvec_mm` | 码中心在相机系下的坐标，单位毫米（与 `marker_size_mm` 同单位，不做隐式换算）。**可见的码必然 `tvec_mm[2] > 0`**，解出负值一律判为错解 |
| `distance_mm` | `||tvec||`，不是 `tvec[2]`。码偏出画面中心时两者不同，抓取要用前者 |
| `tilt_deg` | `acos(-R[2,2])`，即码面法向（指向相机）与「相机朝里的光轴」的夹角，0° = 正对，90° = 侧对。**必须带这个负号**：正视时 `R[2,2] = -1`，写成 `acos(R[2,2])` 会得到 180°（不报错，只是所有倾角都反了） |
| `yaw_deg` | **图像平面内的自转角**：码 x 轴相对图像 +x 轴的方向角，`atan2(R[1,0], R[0,0])`，范围 (−180, 180]；因图像 y 向下，顺时针为正。**不是**「绕码法向的自转角」——只有 `tilt=0` 时两者才相等，倾斜时不能混用。本任务不输出真正的绕法向分解，需要的人直接拿 `rvec`/`R` |
| 重投影误差 | 用解出的 (R,t) 把四个角投回图像，与原角点的欧氏距离求 RMS，单位像素。**它是"这次解算自洽不自洽"的唯一内建指标** |

### 2.3 `solvePnP` 选型

| 方案 | 结论 | 理由 |
|---|---|---|
| `SOLVEPNP_ITERATIVE` | 备选 | 需要初值，平面目标下对初值敏感；默认会给一个粗略初值，近距离可用、远距离容易落到错解 |
| `SOLVEPNP_IPPE_SQUARE` | **选用** | 专为「正方形、共面、四个点」设计，闭式解不需要初值，正是 ArUco 的几何形状 |
| `SOLVEPNP_IPPE` | 备选 | 任意四边形版，我们的四角本来就是正方形，用 SQUARE 版本更稳 |
| `estimatePoseSingleMarkers` | **禁用** | 新版 OpenCV 已弃用（任务单坑 3），且拿不到多解信息 |

配套决定：

1. 解完可选 `cv2.solvePnPRefineLM()` 精化（`pose.refine: true` 默认开），精化前后各算一次重投影 RMS，**只用 RMS 更小的那个**。
2. 用 `cv2.solvePnPGeneric(..., SOLVEPNP_IPPE_SQUARE)` 拿两个解。**实测：IPPE_SQUARE 恒返回 2 个解**，第二解的 `tilt` 与第一解相同、距离只差 0.1–0.5%，两者的旋转夹角恰为 `2×tilt`（15°→30°，60°→120°）；正视角时两解完全重合（夹角 0°）。也就是说——**歧义影响的是姿态，几乎不影响距离**。
   因此判据用两条同时成立：`(rms2 - rms1) / max(rms1, 1e-6) < pose.ambiguity_ratio`（默认 3.0）**且** 两解旋转夹角 > `pose.ambiguity_deg`（默认 10°），才标 `ambiguous=True`。
   **不要用绝对 px 阈值**：同一 tilt 下两解 RMS 差随距离缩小（实测 0.68 px @500 mm、0.34 px @1000 mm），固定 px 阈值会让远处的码被误标。
3. **硬校验重投影 RMS**：超过 `pose.max_reproj_rms_px`（默认 2.0）直接抛 `ValueError`，不是只打日志。理由是 R1 那条错误（模型点顺序写错）与 R4（角点交换）都只表现为 RMS 爆炸，日志里一行 warning 没人会看。
4. **硬校验前向性**：`tvec_mm[2] <= 0` 抛 `ValueError`。这是唯一能抓住 R5（180° 标签错位）的检查——那种情况下重投影 RMS 是 **0.0000 px**，全靠 z 符号暴露。
5. 码倾斜 > 60° 时 OpenCV 检测本身就开始丢（教程第八节），位姿再准也没用，所以 `pose.max_tilt_deg`（默认 75）只用来在日志里提示"这个结果别用"，不做剔除。

### 2.4 去畸变：选「角点归一化」而不是「整帧去畸变」

| 方案 | 做法 | 代价 | 结论 |
|---|---|---|---|
| A 整帧去畸变 | `undistort_image()` 后再检测 | 每帧 1280×1024 全图重映射，会掉帧；`cv2.undistort` 默认保持原尺寸、四角出现黑边并被拉伸；若改用 `getOptimalNewCameraMatrix` 裁剪，则 K 必须同步换，否则口径不一致 | 不选 |
| B 角点归一化 | 原图检测 → `undistort_points(corners)` → PnP 用原 `K` | 每帧只变换 4×N 个点，开销可忽略 | **选** |

**方案 B 的三条坑（都不报错、只让数字偏）**

1. **PnP 的 `dist_coeffs` 必须传 `None`**。角点已被 `undistort_points` 掰直，再传畸变系数等于去畸变两次。实测（`k1=-0.30, k2=0.12`）：距离 498.20 mm vs 正确 501.30 mm，偏 **0.62%**；畸变越大、码越靠画面边缘，偏差越大。
2. `camera_matrix` 用**标定原 K**，不要传 `getOptimalNewCameraMatrix` 的结果——那是给方案 A 准备的。
3. 畸变系数有 `k3` 时 OpenCV 会按 5 个参数解包；本仓库标定默认固定 `k3`（`tools/calibrate_camera.py`），传 `None` 后这些细节都不影响，但**不要**为了"更准"把 `D` 和已掰直的角点一起传进去。

另有一个独立坑：**换分辨率必须重标定**。标定在 1280×1024 做，回放 640×480 的图时直接套同一个 K，内参和图像尺寸不匹配 → 距离整体偏、且程序不报错。`pose` 初始化时校验 `intrinsics.image_size` 与帧尺寸，不一致就 `log.warning` 并打出两个尺寸（默认只警告不中断：缩放回放是常见调试手段，硬拦反而挡路）。

### 2.6 契约级定义（写进 `docs/interface.md`）

```python
@dataclass(frozen=True)
class MarkerPose:
    marker_id: int
    rvec: np.ndarray        # (3,) float64，Rodrigues 旋转向量
    tvec_mm: np.ndarray     # (3,) float64，码中心在相机系下的坐标，毫米；[2] 恒 > 0
    distance_mm: float      # ||tvec_mm||
    tilt_deg: float         # 码面法向与光轴夹角，0~180
    yaw_deg: float          # 图像平面内自转角（顺时针为正），(-180, 180]
    reproj_rms_px: float    # 四角重投影 RMS
    ambiguous: bool = False # 两解的相对 RMS 差 < 3 倍且旋转夹角 > 10°

def estimate_pose(marker, marker_size_mm, camera_matrix, dist_coeffs=None,
                  refine=True) -> MarkerPose
def estimate_poses(markers, marker_size_mm, camera_matrix, dist_coeffs=None,
                   refine=True) -> list[MarkerPose]   # 保持入参顺序
```

六条与 `ArucoMarker` 同风格的约定：

1. 无码输入 `[]` → 返回 `[]`，不抛异常。
2. 输出顺序与输入 `markers` **一致**（`estimate_poses` 不做排序，排序是检测器的事）。
3. `marker_size_mm <= 0`、`camera_matrix` 形状不是 (3,3)、角点形状不是 (4,2) → 抛 `ValueError`，报错里写清期望与实际。
4. `rvec`/`tvec_mm` 一律 `float64`：它们是几何量，不学 `corners_px` 用 float32。
5. `reproj_rms_px > pose.max_reproj_rms_px` → 抛 `ValueError`。**这条不是防御性编程，是抓"模型点顺序写错"和"角点被交换"的唯一入口**（实测这两种情况的 RMS 是 5930 px 和 73.8 px，而其余输出看起来都很正常）。
6. `tvec_mm[2] <= 0` → 抛 `ValueError`（可见的码不可能在相机后方）。抓 180° 标签错位：那种情况 RMS 是 **0.0000 px**，只有 z 符号不对。

## 三、任务 3（识别效果测试）技术方案

### 3.1 真值从哪来 —— 这是整件事的地基

**没有真值就只能说"看起来对"，不能说"误差 2%"**。两条来源：

| 来源 | 做法 | 能测什么 | 成本 |
|---|---|---|---|
| 合成渲染（主） | 已知 `(R,t)` + `K` → `cv2.projectPoints` 得四角理想像素 → `getPerspectiveTransform` 把 `generateImageMarker` 的图 warp 到背景 → 输出图 + 真值 JSON（含 `R`、`t`、四角像素） | 距离/倾角/滚转/光照/噪声/模糊 全维度可控，每档可重复，真值是浮点精确值 | 一次开发，之后批量刷 |
| 真机（辅） | 卷尺量距离 + 支架固定角度拍照 | 只能测**单点距离**（与 `distance_mm` 比），姿态无真值 | 手工，样本少 |

合成渲染的**自洽性检查**（必做，否则渲染错了会误判算法）：把真值 `(R,t)` 和自己投出来的四角喂回 `estimate_pose`，误差必须是 0（<0.01 px）。这一步不通过说明渲染或口径写错了。

渲染器的三条硬要求（少一条就会造出"算法失败"的假样本）：

1. **码周围必须留白边**，背景用浅色（灰度 200–250）。码的黑边框一旦和深色背景连成一片，检测必然失败，而这与位姿算法无关（教程第八节）。
2. warp 用的目标四边形必须就是 `projectPoints` 算出的四角，**不要**另外用缩放/旋转拼，否则真值与图像差一点点，误差表里会多出一层系统性偏差。
3. **本版不注入镜头畸变**（只在单元测试里用畸变角点验方案 B）。这是一处显式的范围裁剪：合成数据相当于"理想针孔相机"，真机的边缘畸变由 S2b / S9 的真机抽测覆盖。若后续发现合成与真机结论差得远，第一件事是把畸变注入补上（用 `cv2.remap` 按标定参数反查采样）。

### 3.2 扫描矩阵

| 维度 | 档位 | 目的 |
|---|---|---|
| 距离 | 300 / 450 / 675 / 1000 / 1500 / 2000 mm（等比 1.5） | 找检出率拐点；距离误差随 z 增长的趋势 |
| 倾角（tilt） | 0 / 15 / 30 / 45 / 60 / 75° | 验证教程"超 60° 很勉强"这条经验在本机 K 下的具体位置 |
| 滚转（yaw） | 0 / 90 / 180 / 270° | 验证旋转不变性；同时看 `yaw_deg` 是否跟着转 90° |
| 光照 | 亮度因子 0.35 / 0.60 / 1.00 / 1.40，另加一档"过曝裁剪"（≥250 截断） | 过暗/过曝对二值化的影响 |
| 噪声 | σ = 0 / 8 / 16 | 低照度下的等效噪声 |
| 运动模糊 | 线性核长度 0 / 5 / 9 / 13 px | 对应相机 80 ms 曝光下人举码晃动（`configs/default.yaml` 已记这条实测） |
| 分辨率 | 1280×1024（标定口径）与 640×480（缩放回放） | **专测 2.4 节那个"内参尺寸不匹配"的坑** |

组合爆炸控制：一次只动一个维度（单因素扫描），其余固定在「450 mm / tilt 0 / yaw 0 / 亮度 1.0 / 无噪无模糊」。合计约 6+6+4+5+3+4+2 ≈ **30 张图 × 至少 1 个码**，全部合成，秒级。

### 3.3 指标定义

| 指标 | 公式 / 取法 | 说明 |
|---|---|---|
| 检出率 | 检出帧数 / 总帧数 | 码"没了"就是这个降 |
| ID 正确率 | ID 正确的码数 / 检出的码数 | 它与检出率分开算：认错比漏检更危险 |
| 距离相对误差 | `|d_est − d_true| / d_true` | **主指标**，抓取精度直接挂钩 |
| 倾角绝对误差 | `|tilt_est − tilt_true|`（度） | 抓取姿态用 |
| yaw 误差 | `min(|Δ|, 360−|Δ|)`（度） | 处理 ±180 环绕，别用绝对值差 |
| 重投影 RMS | `pose.reproj_rms_px` | 内建自洽指标，>1.5 px 的样本要单独看 |
| 单帧耗时 | `time.perf_counter()` 包住 detect+pose，取中位数 | 实时性下界，1280×1024 单码目标 < 30 ms |

### 3.4 失败原因分析框架（第 3 条任务的"分析"部分）

按**可测量的根因**分类，每类给判据和验证方法，不写"可能是光照问题"这种结论。

| # | 根因 | 判据 | 怎么验证 |
|---|---|---|---|
| 1 | 码太小：每格像素数低于下限 | 每格像素 = 码边长像素 / 6，教程给的硬下限是 5–10 | 输出「每格像素 vs 检出率」曲线，拐点就在下限附近；这条能把"距离太远"翻译成可复现的数字 |
| 2 | 透视过斜 | tilt 档位对应的检出率悬崖 | 单独扫 tilt，看悬崖落在 60° 还是更早；同时看 `corners_px` 是否开始抖 |
| 3 | 过曝 / 欠曝导致二值化失败 | 灰度均值与 250 截断像素占比 | 输出「亮度因子 vs 检出率」；过曝档看白格是否被并进背景 |
| 4 | 运动模糊 | 曝光期内位移（px/帧）；80 ms 下实测 20 px ≈ 一个格子 | 模糊核扫描 + 真机降曝光到 40 ms 复测（`configs/default.yaml` 已记录这条） |
| 5 | 角点定位漂移 | `reproj_rms_px` 随距离上升 | RMS 反弹但 ID 正确 → 是角点精度问题，不是检测问题 |
| 6 | 标定残留 / 分辨率不匹配 | 误差随距离**成比例**增长 | 若距离误差是"整体乘性偏移"→ 先查 K 与 `image_size`；若是"随距离放大"→ 查畸变与角点 |
| 7 | 边长填错 | 距离误差与距离无关、是常数比例（如恒定 +53%） | 量尺子。这条**重投影 RMS 完全看不出来**，是坑 40 的位姿版本 |

## 七、需要你（或搭档）确认的 4 件事

1. **码的实际边长（mm）**：量黑框外沿。这一条不定，所有距离数字都是错的。
2. **内参文件在哪**：搭档那份 `configs/camera_calibration.yaml` 能否传一份？`image_size` 是 1280×1024 还是别的？
3. **验收场景**：任务 2 是要「实时窗口上看到坐标轴」，还是「离线批量出位姿表」就够？（影响 D2 上午的工作量）
4. **真机可用性**：现在能否取帧做 S9 的抽测？不能的话任务 3 的结论只到合成数据，真机部分标"未验证"。

### 拿不到内参时的交付边界（先讲清，免得最后扯皮）

|---|---|

- `viz/draw.py::draw_detections` 已支持 `ArucoMarker`，返回新图；坐标轴需新增函数
- `cli.py` 现有 `run()`（判色批处理）与 `run_aruco_live()`（ArUco 实时）两个入口
- 测试现状 59 项；`tools/aruco_check.py` 是"逐图比真值 + 打印汇总 + 退出码"的现成骨架
