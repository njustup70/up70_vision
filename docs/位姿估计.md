# ArUco 位姿估计：原理、口径与实测

> 对应任务单第 2 条（位姿估计）与第 3 条（识别效果测试）。
> 代码：`pose.py`（解算）、`tools/pose/`（逐图核对）、`pose-check --sweep`（扫描报告）。
> 命令统一走 `python -m vision pose-check`（旧的 `scripts/pose_check.py` 薄壳已于 2026-10-22 删除）。
> 前置：相机内参（`docs/相机标定.md`）+ 码的实际边长（卡尺量）。

## 一、这件事在干嘛（不用公式版）

相机拍到一张纸上的方块码，检测器告诉你"这是 7 号码，四个角落在图像的第 616/663 列那一片"。
但这只是**像素**。位姿估计要回答的是另外三个问题：

- 它在我正前方**多少毫米**？
- 它**斜了多少度**（正对着我，还是侧着）？
- 它在画面里**转了多少度**（贴纸歪着贴的）？

做法是一次几何换算（PnP）：

```
  input A: 4 corners on the paper     -> known 3D coords (side length measured)
  input B: 4 corners in the image     -> pixels from the detector
  input C: camera intrinsics          -> pixels to angles (fx, fy, cx, cy)
                     \                /
                      >-- solve PnP --<          -> marker pose:
                     /                \             t (mm) + R (orientation)
```

四个点 ↔ 四个点，解出 6 个未知数（3 个平移 + 3 个旋转）。数学上叫 PnP，
OpenCV 里是 `solvePnP`；ArUco 相当于"自动找点"版本的标定板。

**为什么必须量边长**：整条链路里，唯一提供"尺度"的就是码的边长。边长填成 2 倍，
所有距离就都是 2 倍，而重投影误差一点都不会变大——程序不会报错（`progress.md` 坑 40
的位姿版本）。

## 二、口径（写死，全仓同一套）

| 项 | 约定 |
|---|---|
| 码坐标系 | 原点在码中心、码面 `z=0`；x 轴指向码的右边、y 轴指向码的上边、z 轴垂直纸面**指向相机** |
| 四角顺序 | `(-L/2,+L/2) (+L/2,+L/2) (+L/2,-L/2) (-L/2,-L/2)` ↔ 图像的 TL/TR/BR/BL。**这是 `SOLVEPNP_IPPE_SQUARE` 的硬性要求，顺序错了不报错、只给垃圾** |
| 相机坐标系 | OpenCV 光学系：x 右、y 下、z 沿光轴朝前 |
| `tvec_mm` | 码中心在相机系下的坐标，毫米；可见的码恒有 `tvec_mm[2] > 0` |
| `distance_mm` | `‖tvec_mm‖`（斜距），不是 `tvec_mm[2]`；码偏出画面中心时两者不同 |
| `tilt_deg` | `acos(-R[2,2])`。**负号不能丢**：正视时 `R = diag(1,-1,-1)`，`R[2,2] = -1`，写成 `acos(R[2,2])` 会让所有倾角变成 180°−真值，且不报错 |
| `yaw_deg` | 码 x 轴在图像平面内的方向角 `atan2(R[1,0], R[0,0])`，图像 y 向下故顺时针为正 |
| 单位 | 边长进、距离出，一律毫米 |

实测确认（40 mm 码、200 px、正视）：`R = diag(1,-1,-1)`、`tilt = 179.90°`（未取负号时）、
距离 160.8 mm（理论 160.0）。

## 三、怎么跑

```bash
# 1) 逐张核位姿：真值 / 估计 / 误差 并排，超阈值标 ⚠️
python -m vision pose-check --dir output/pose_scenes_825 --marker-mm 82.5

# 2) 真机图（有内参、有卷尺量出的边长）
python -m vision pose-check --dir data/pose/real \
    --intrinsics configs/camera_calibration.yaml --marker-mm 82.5

# 3) 实时：终端与画面 HUD 同时出 d / tilt / yaw，画面上多三根坐标轴
python -m vision live \
    --set detector.name=aruco --set input.source=camera \
    --set pose.enabled=true --set pose.marker_size_mm=82.5

# 4) 精度扫描：31 个合成场景，出 raw.csv + summary.md + 8 张图
python -m vision pose-check --sweep --marker-mm 82.5 \
    --intrinsics configs/camera_calibration.yaml --out output/pose_sweep/20261019_825
```

> 当前的码边长是 **82.5 mm**；**棋盘格的方格边长是 23 mm**，那是标定用的另一个尺寸，别混。

内参从 `configs/camera_calibration.yaml` 读（`calibration.file`，相对 `configs/` 解析）。
仓库**强制入库了一份默认快照**（本机 2026-10-19，33 视图，RMS 0.473 px），所以新 clone 也能直接跑；
重标定会覆盖同一路径，提交前确认是不是全队约定的那台相机。
`calibration.required=false`（默认）时找不到内参只关掉位姿、其它照跑；改成 `true` 则没内参就退出码 2。

## 四、实测数字（合成图）

合成图无镜头畸变、边缘理想，属**识别能力上限**。两批码分开记：

### 4.1 当前批次：82.5 mm 码（2026-10-19，fx=1321.67，RMS 0.473 px）

`pose_check` 通过 **29/31**；失败项固定为 `bright_300`（3.0 倍过曝未检出）与
`blur_13`（检出但 RMS 2.74 px 超限、拒绝出解）。

| 维度 | 档位 | 距离误差 | 倾角误差 | 结论 |
|---|---|---|---|---|
| 距离 | 300 / 450 / 675 / 1000 mm | 0.09% / 0.10% / 0.17% / 0.04% | 正视，不判 | 距离准 |
| 距离 | 1500 / 2000 mm | 0.15% / **0.41%** | 正视，不判 | 每格 12.1 / 9.1 px 仍可用 |
| 倾角 | 15 / 30 / 45 / 60 / 75° | 0.02% / 0.40% / 0.14% / 0.01% / 0.13% | **0.05–0.42°** | 倾斜后姿态很准 |
| 噪声 / 滚转 / 640×480 | σ=0/8/16、0–270°、缩放 | 0.04%–0.25% | 0.00–0.26° | 全过 |

与小码相比，模糊档改善最大：9 px 拖影的距离误差从 8.2% 降到 0.25%（每格像素从 11 涨到 40）。

### 4.2 旧批次：23 mm 码（2026-10-18，fx=1292.66，RMS 0.507 px）

下表全部用 23 mm 码测得，**不能与 4.1 直接对比**（成像尺寸差 3.59 倍）。

| 维度 | 档位 | 距离误差 | 倾角误差 | 结论 |
|---|---|---|---|---|
| 距离 | 300 / 450 / 675 mm | 0.11% / 0.30% / 0.84% | 6.5° / 10.0° / 5.7° | 距离准，倾角不准（正视弱可观） |
| 距离 | 1000 / 1500 mm | 0.16% / 0.15% | 13.5° / 16.5° | 同上 |
| 距离 | 2000 mm | 3.94% | 4.2° | 码只有 15 px，量化误差占主导 |
| 倾角 | 15 / 30 / 45° | 0.56% / 1.03% / 1.08% | **0.71° / 0.62° / 0.54°** | 一旦真的倾斜，倾角立刻准 |
| 倾角 | 60 / 75° | 0.46% / 0.50% | **0.05° / 0.66°** | 60° 仍稳定；75° 临界（本例检出，40 mm 码时未检出） |
| 滚转 | 0 / 90 / 180 / 270° | 0.30% 量级 | 见上（正视档） | 旋转不变性成立，yaw 跟着转 |
| 亮度 | 0.35 / 0.6 / 1.0 / 1.4 / 2.2 倍 | 0.20–0.30% | 8–10°（正视） | 全过；2.2 倍配环境光 60 发灰但仍能认 |
| 亮度 | 3.0 倍 + 环境光 110 | — | — | **未检出**（白格截顶、黑框抬到约 245） |
| 噪声 | σ = 0 / 8 / 16 | 0.30% / 0.30% / 0.30% | — | 全过（三档几乎无差，说明合成图的信噪比远高于实拍） |
| 运动模糊 | 0 / 5 px | 0.30% / 0.33% | — | 通过 |
| 运动模糊 | 9 / 13 px | **9.9% / 12.2%** | **28.4° / 31.0°** | 检出了，但四角被拖影拉偏 |
| 分辨率 | 1280×1024 → 640×480 | 0.30% / 0.38% | — | 每格 11.3 px → 5.5 px 仍可用 |

**怎么读这张表**（三条都是踩过之后才明白的）：

1. **距离很稳，倾角在正视附近不可靠——这不是 bug，是几何**。码正对相机时，绕 x/y 轴转
   10° 只让投影高度缩 1.5%（67 px 的码差 1 px），与角点定位噪声同量级，所以正视时的
   倾角误差实测能到 4–16°；一旦倾斜 15° 以上，误差立刻降到 1° 以内。**要拿姿态去抓取，
   先看 `tilt_deg`：接近 0 的姿态数字不可信，接近 60° 的反而最准。**
2. **重投影 RMS 小 ≠ 姿态准**。四个点没有冗余，PnP 总能精确穿过这四个点（RMS 恒在
   0.01–0.6 px），所以误差再大 RMS 也不会报警。判断姿态靠不靠得住要看 `tilt_deg` 与场景，
   不能看 RMS——这也是 `pose_check` 在真值倾角 < 10° 时不判倾角的原因。
3. **每格像素是最实用的判据**。把"距离太远"换算成"码的一格占几个像素"（边长 ÷ 6），
   合成图上 2.5 px 都还能检出；但教程给的 5–10 px 是**实拍**下限，合成图无噪声、
   无压缩、边缘是理想直线，属于上限，不能直接搬到场上。

## 五、失败排查（按现象定位，别猜）

| 现象 | 先查什么 | 为什么 |
|---|---|---|
| 距离整体偏一个固定比例（如都大 53%） | 码边长是否实测 | 边长是唯一的尺度来源；重投影误差完全看不出来 |
| 距离误差随距离放大、且码在画面边缘更大 | 内参尺寸是否与图像一致、角点是否去了畸变 | 换分辨率不重标定、或二次去畸变，都会让误差"越远越大" |
| 倾角全都在 160–180° 附近 | `tilt` 公式的负号 | `acos(R[2,2])` 与 `acos(-R[2,2])` 差一个补角 |
| 解算直接抛"重投影误差过大" | 模型点顺序、角点是否被交换 | 顺序错实测 993 px、交换两点 240 px，都与图像内容无关 |
| 同一张图偶尔给出方向完全不同的姿态 | `ambiguous` 标记 | 平面位姿天然两解（夹角 `2×tilt`、距离差 <0.5%）；正视角下两解重合 |
| 码明明看得见，位姿却报错 | 是否"完全正对且严格居中" | IPPE_SQUARE 在严格对称输入上会退化：要么两个候选一起锁到 180° 分支，要么直接变成 NaN。`solve_pose` 会先过滤非有限解、再用 ITERATIVE 兜一次；仍失败时错误文本会区分"数值退化"与"顺序错" |

## 六、已知的坑（都会"不报错，只让数字错"）

1. **模型点顺序**：`SOLVEPNP_IPPE_SQUARE` 对四个点的顺序有硬要求。实测把顺序写成
   "y 向下"那一套：真值 160.8 mm 的码解出 0.00 mm、RMS 993 px。
2. **二次去畸变**：角点已 `undistort_points()` 后，PnP 必须传 `dist_coeffs=None`。
   再传一次：画面中心偏 0.62%，偏心处偏 **14.6%**。
3. **180° 角点错位**：正方形对称，四角整体循环平移两位（等价于码转 180°）时
   距离、倾角、RMS 全不变，只有 `yaw` 差 180°。**位姿层分辨不出来**，
   顺序只能靠检测层保证（`tests/test_aruco.py` 的上边倾角断言）。
4. **IPPE_SQUARE 退化分支**：完全正对且严格居中的输入会让两个候选解一起锁到 180°
   （RMS 38.6 px 而真解 0.01 px），或者一起变成 NaN（23 mm 码、300 mm、合成内参 `cx=640`；
   同一张图换 float32 角点反而不退化）。现在先过滤非有限解，再对"最优解仍过不了 RMS 门槛"
   的情况用 ITERATIVE 兜一次。NaN 之所以危险，是因为 `nan > limit` 恒为 False，
   所有基于比较的校验都形同虚设。
5. **纯乘亮度模拟不了过曝**：黑框乘 2.2 仍是 0、白格仍是 255，五档全过等于没测。
   真过曝是"环境光把黑框照亮 + 增益把白格截顶"，所以 `PoseSpec.ambient` 必须先加后乘。
6. **长度单位**：字段名一律带 `_mm`。混用 mm/m 差 1000 倍，而 PnP 本身不检查。
7. **画轴与解算的口径必须成对**：位姿若是带 `D` 解出来的（原始畸变像素空间），画轴也要带同一个
   `D` 投影；固定用 `dist=None` 会让轴与四个角在画面边缘错开几像素。反之，角点已
   `undistort_points(..., P=K)` 掰直时两边都传 `None`。
8. **默认边长不是安全值**：`pose.marker_size_mm` 默认 23.0 是**上一批**码的历史值，
   当前批次是 **82.5 mm**，用默认值会让距离偏到 0.279 倍，而重投影误差完全正常。
   换码必须重量，并且**每次显式传** `--marker-mm` / `--set pose.marker_size_mm`。
9. **棋盘格边长不是码边长**：标定用的方格是 **23 mm**（`--square-mm 23`），与 ArUco 码的
   82.5 mm 是两件事；把 23 填进 `marker_size_mm` 就是上一条那个 0.279 倍的错误。

## 七、明确不做

| 项 | 原因 |
|---|---|
| 多码联合位姿（多码融合求相机位姿） | 需要先定场地坐标系；本任务只要单码相对位姿 |
| 码在场地坐标系里的绝对位姿 | ID→场地坐标的对应表还没有（物块与场地未定） |
| 时间滤波（卡尔曼 / 滑动平均） | 位姿噪声特性还没在真机上测过，先滤波等于用错误模型掩盖问题 |
| 换字典（`DICT_5X5_50` 等） | 任务单指定 `DICT_4X4_50`，换字典会让 `assets/aruco/` 的 9 张真值图组作废 |
| 整帧去畸变再检测 | 每帧全图重映射会掉帧；角点归一化（只变 4×N 个点）效果等价、开销可忽略 |
