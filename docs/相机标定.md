# 相机标定：内参、畸变系数与重投影误差

> 代码：`core/calibration.py`（算法）、`tools/calibrate_camera.py`（采图 + 解算）、`tools/gen_chessboard.py`（造打印板）。

---

## 一、标定到底在解什么

镜头不是理想的小孔成像。真实镜头有两件事和"理想"不一样：

1. **焦距和光心**：每个像素对应哪个方向，由 `fx / fy / cx / cy` 四个数决定；
2. **畸变**：画面边缘被拉弯，直线拍出来是弧线，靠 `k1 / k2 / p1 / p2 / k3` 五个数描述。

这两组数合起来，就能把「像素坐标」和「相机坐标」互相换算——后续所有几何量（物块在相机前方多少毫米、码的位姿、抓取点）都从这里出发。**没标定，像素只是像素；标定后，像素才能变成毫米。**

标定的做法：拿一块**格子边长已知**的黑白棋盘，在镜头前摆十几个不同姿势各拍一张。每张图里，我们既知道角点的真实坐标（板子上的毫米位置），也知道它落在图上的哪个像素——用足够多的这种对应关系，就能反解出上面那 9 个数。

## 二、内参矩阵：4 个数，各管什么

```text
        ⎡ fx   0   cx ⎤
   K =  ⎢  0  fy   cy ⎥
        ⎣  0   0    1 ⎦
```

| 符号 | 含义 | 常见量级（1280×1024、约 6 mm 镜头的相机） |
|---|---|---|
| `fx` | x 方向焦距，**单位是像素**（不是毫米） | 700 ~ 2000 |
| `fy` | y 方向焦距，通常 `fy ≈ fx`（差太多说明像素不是正方形，或标定有问题） | 同上 |
| `cx` | 光心（光轴穿过的像素），理想是画面正中 `width/2` | 1280×1024 时约 640 |
| `cy` | 同上，纵向 | 约 512 |

> **内参和「板子多大」无关**：同一批图，`--square-mm` 填 15 还是 23，解出的 `fx/fy/cx/cy` 与畸变**完全一样**——
> 尺度信息被每张图的位姿（距离）吸收掉了。`square_mm` 决定的是「这块板子离相机多远」以及下游把像素换算成毫米的口径。
> 填错不会让内参错，但会让**位姿估计算出的距离**整体偏（偏多少 = 真实边长 / 填错边长）。

**为什么焦距的单位是像素？** 因为它把"方向"换算成"偏移"：

```text
u = fx · (X/Z) + cx
```

同样大小的物体，距离越远（Z 越大），在图上占的像素越少——比例系数就是 `fx`。想知道"多少像素等于多少毫米"，得配合工作距离：在 500 mm 处，1280×1024、`fx=800` 的相机，视野宽约 `1280 × 500 / 800 = 800 mm`，即 **1 像素 ≈ 0.63 mm**。这个换算是阶段二做位姿估计时要反复用的。

> `fx / fy` 与"像素物理尺寸、真实焦距"的关系是 `fx = f_mm / pixel_mm`。所以同一个镜头换一台分辨率不同的相机，`fx` 会跟着变——**内参只对"这台相机 + 这个分辨率 + 这个对焦状态"成立**。

## 三、畸变系数：5 个数，各管什么

摄像机的畸变主要是两种：

### 1. 径向畸变（`k1, k2, k3`）：桶形 / 枕形

离画面中心越远，像素被拉得越开（或越挤）：

```text
x_distorted = x · (1 + k1·r² + k2·r⁴ + k3·r⁶)
y_distorted = y · (1 + k1·r² + k2·r⁴ + k3·r⁶)
```

`r` 是到光心的归一化距离。**符号怎么读**：

| 现象 | 系数 | 长什么样 |
|---|---|---|
| 桶形（barrel） | `k1 < 0`（最常见） | 画面四角向外鼓，直线往外弯 |
| 枕形（pincushion） | `k1 > 0` | 四角向内收 |

`k1` 管得最多，`k2` 修中段，`k3` 修最外圈（也最不稳，样本不够时容易乱跑）。所以有些团队干脆把 `k3` 固定为 0（`cv2.CALIB_FIX_K3`）。

### 2. 切向畸变（`p1, p2`）：镜头装歪了

镜头与感光面没完全平行时，画面会往一个方向斜一点：

```text
x_distorted = x + 2·p1·x·y + p2·(r² + 2·x²)
y_distorted = y + p1·(r² + 2·y²) + 2·p2·x·y
```

`p1 / p2` 通常很小（1e-3 量级），但一并解出来更稳。

> **顺序是契约**：OpenCV 的约定是 `[k1, k2, p1, p2, k3]`（见 `core/calibration.py` 的 `DIST_ORDER`）。自己重排不会报错，只会让去畸变"歪一点"，很难查。

## 四、重投影误差 RMS：怎么判断标得好不好

标定完之后，用解出来的参数把每个板子角点**重新投影**回图像，和实际量到的位置比距离，算均方根误差（`cv2.calibrateCamera` 返回的 `ret`，单位像素）：

| RMS | 判据 | 说明 |
|---|---|---|
| < 0.5 px | **好** | 亚像素级一致，可以直接用 |
| 0.5 ~ 1.0 px | 可用 | 能用，但值得重拍一批图试试 |
| > 1.0 px | 别直接用 | 板子没贴平、有反光、图太少、或板子参数（格子数/边长）填错了 |

**注意：RMS 小不等于标定准。** 所有图都在同样距离、同样角度拍，也能把 RMS 压得很低，但 `fx` 会偏——因为平面靶标下"焦距"与"距离"是耦合的。所以取图要**把板子挪遍整个画面**（近/远、左/右/上/下、正对/大角度倾斜）。

## 五、怎么标（三步）

### 1. 造一块板子并打印

```bash
# 同时生成 PNG（带 300 dpi 元数据）和一份物理尺寸精确的 PDF
python -m up70_vision gen-chessboard --cols 9 --rows 6 --square-mm 15 \
  --out assets/calib/chessboard_9x6_15mm.png
```

**打印时优先用生成的 PDF**（纸张 A4、缩放选「实际大小 / 100%」）：PDF 的页面尺寸写成精确的物理尺寸
（点 = 1/72 英寸），打印机不会去猜 DPI，印出来就是 1:1。用 PNG 也行，但它依赖驱动读 DPI 元数据——
我们踩过的坑正是 PNG 没写 DPI、驱动按 200 dpi 猜，把 15 mm 打成了 23 mm。

- `--cols/--rows` 是**内角点**个数，不是格子数（10×7 格 → 9×6 内角点）；
- 打印后**用尺子量一个格子的实际边长**，把量到的值填给标定工具。这不是形式主义：我们这台打印机把
  「15 mm」实际打成了 **23 mm（+53%）**——按 15 填的话，位姿估计出的距离会整体少算 35%；
- 贴到硬纸板上：纸一弯，畸变系数会把"纸的弯"也学进去。

> **采图时工具会自动挡掉两种坏图**（这是实拍踩坑后加的）：
> ① **没站稳**（连续 3 帧姿态几乎不变才收）——防手持运动模糊；
> ② **和其它张太像**（位置/格距/角度都接近就不收）——防"连拍七张同一姿势"把焦距带飞（坑 43）。
> 窗口左上角会显示 `hold still` / `too similar to #4` / `saved 3/15`，照着做即可。

### 2. 采图并解算

```bash
# 现场采（走相机，每看到一次完整棋盘就存一张，凑够 15 张自动标定）
python -m up70_vision calibrate --capture 15 --board 9x6 --square-mm 23

# 或者先用手机拍好图，再对着目录标
python -m up70_vision calibrate --images data/calib --board 9x6 --square-mm 23
```

`--square-mm` **必填**，且要填**量到的**值。示例里的 23 就是我们这块板的实测值
（设计 15 mm，打印机放大到 23 mm）；填标称值的话内参照样对，但位姿距离会整体偏 53%。

### 2.5 补拍（想更准时）

**不用重来**：已有图留在 `data/calib/`，补拍时工具会
① 从下一个可用编号接着存（不会覆盖旧图）；
② 读一遍旧图的姿态，**不会收同一个姿势**；
③ 采完对**整个目录**重新标定（旧图也算进来）。

```bash
python -m up70_vision calibrate --capture 8 --board 9x6 --square-mm 23 \
  --set input.source=camera --set input.camera.exposure_us=40000 --preview
```

想推倒重来就加 `--fresh`（编号从 1 开始、会覆盖同目录旧图）。

### 3. 看结果并复核

工具会先标一次，再**按单张 RMS 剔掉离群图**重标一次（比中位数大一倍以上的挑掉，剔了谁都会打印）。
默认还把 6 次径向项 `k3` 固定为 0：普通镜头用不到它，放开会让 k1/k2/k3 互相抵消（实测 rms 几乎不变、系数却失真）。广角/鱼眼才加 `--free-k3`。

```bash
python -m up70_vision calibrate --from configs/camera_calibration.yaml
# 期望：rms < 0.5，fx ≈ fy，cx ≈ width/2，cy ≈ height/2
```

结果写在 `configs/camera_calibration.yaml`（**每台相机一份，`.gitignore` 已排除**）。仓库里另外
**强制入库了一份默认快照**（本机 2026-10-19，33 视图，RMS 0.473 px），让新 clone 的位姿能直接跑；
重标定会覆盖这个路径，提交前确认是不是全队约定的那台相机，只想临时用别的标定请 `--intrinsics` 指定。

## 六、取图的 6 条经验（照做能一次过）

1. **板子占画面 1/3 以上**：太远了角点挤成一团，亚像素精化会失效，标出来的参数是垃圾；
2. **把画面四个角都拍到**：畸变在边角最明显，只在中间拍，畸变系数几乎解不出来；
3. **两种距离、三四种角度**：正对 + 倾斜 30~45°，近 + 远各来几张；
4. **避免反光与过曝**：格子上出现大片高光，角点会被吃掉（可换成哑光纸，或把光源挪开）；
5. **板子别出画**：只拍到半个棋盘时 `findChessboardCorners` 直接失败（工具会跳过并告诉你）；
6. **15~30 张足够**，同一姿势拍十张没有意义——**多样性**比数量重要。

## 八、这份结果怎么被下游用

阶段二的位姿估计（`solvePnP`）会读 `configs/camera_calibration.yaml`：

```text
内参 K + 畸变 ──→ solvePnP(角点的像素坐标, 码的真实边长) ──→ 码相对相机的 3D 位置与姿态
去畸变       ──→ 直线变直，画框/投影才对得上
```

所以**标定是位姿估计的前置条件**：`fx` 偏 2%，算出来的距离也偏 2%（500 mm 处偏 10 mm）——抓取精度直接受影响。
