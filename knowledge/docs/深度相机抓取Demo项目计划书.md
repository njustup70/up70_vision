# 深度相机抓取 Demo 项目计划书

## 文档说明

- 目的：尽快得到一个可跑的深度相机 demo，为吸盘机械臂提供物块的三维位置与吸附方向。
- 本文只做任务拆解，不写实现细节。算法细节见 `深度相机融合学习方案.md`（该文档未入库时以官方规格书为准），日级学习节奏见 `8周学习计划-深度相机与C++.md`，ROS 接入与包结构见 `ROS2接入方案-深度相机与YOLO.md`，数据采集与合成数据见 `数据方案-真实采集与合成数据.md`。
- 基准：包结构以仓库瘦身分支的扁平结构（`vision/`、`ros2_ws/`、`lab/`）为准；该结构未落地前，import 路径按现状 `up70_vision` 理解。
- 路径一律相对仓库根。

## 一、目标与边界

### 1.1 一句话目标

相机看一眼桌面，输出「这里有一个物块，吸附点在基座系 (x, y, z)，应该沿法向 n 靠近」，机械臂据此吸起它。

### 1.2 分三段交付

相机在手，但暂时没有固定支架，吸盘闭环也无法验证。所以交付拆成三段，前两段都不依赖固定安装。

| 阶段 | 内容 | 依赖 | 状态 |
|---|---|---|---|
| **第零段（当前目标）** | 真实数据跑通整条链路：取流 → 反投影 → 分割 → 聚类 → 可吸性 → 输出坐标，用**手工真值**算误差；合成数据补拍不出的场景 | 相机（有）+ 临时固定 | **可立即开工** |
| 第一段 | 正式安装，标定到基座系，输出吸附点与法向 | 支架 + 基座位姿 | 待安装条件 |
| 第二段 | 机械臂移动到预吸附位并吸起物块 | 吸盘可用 + 机械臂能执行位姿 | 待解锁 |

**第零段的价值在于：代码是同一套。** `core.detect_grasp_targets(depth_mm, intrinsics, params)`（2D 框为可选参数，见 ROS2 接入方案 12.2）不知道数据从哪来，换数据源只是换上游节点——真实 bag、`fake_camera_node`、真相机三路共用同一条代码路径。所以第零段跑通的东西，第一段直接能用。

第零段的数据方案见 `数据方案-真实采集与合成数据.md`，核心是三点：**真实数据定方向，合成数据量误差**；真实数据靠手工测量造真值；合成数据补反光、边缘、遮挡这些拍不出来的场景。

**第零段的完成定义是 M2 + M3（真实数据误差数字 + 合成补位），第一段的完成定义是 M5（基座系）。** 第一段不要求机械臂动，但要求输出的是基座系坐标而不是相机系坐标——控制组拿到基座系坐标就能开始写他们那一侧，拿相机系坐标等于没用。基座系标定依赖固定支架，所以 M5 必须排在 M4（正式安装）之后。

### 1.3 交付物

| 交付物 | 形式 | 验收 |
|---|---|---|
| 真实数据采集 | `bags/*` + `meta.yaml` | bag 能回放，高度/倾角/物块位置有记录 |
| 深度相机数据通路 | ROS2 launch | 深度、彩色、点云三路都有频率 |
| 单目标检测节点 | ROS2 节点 | 输出抓取目标数组，RViz 可视化正确 |
| 误差统计 | `lab/eval_accuracy.py` | 真实数据中位数 < 15mm，合成数据中位数 < 10mm（口径与数据方案第八节一致） |
| 合成数据与真值 | `lab/gen_synthetic_depth.py` + `fake_camera_node` | 五场景，深度差 = `高 × cos(倾角)` |
| 相机正式安装 | 实物 + 装配说明 | 手推相机无位移，线缆不受力 |
| 手眼标定结果 | YAML + 静态 TF | 标定板实测误差 < 15mm |

### 1.4 明确不做

这一节比上面重要。不划掉这些，demo 会膨胀成一个赛季项目。

| 不做 | 理由 |
|---|---|
| 6D 位姿估计（物体 yaw、形状、尺寸） | 吸盘轴对称，不需要 |
| 夹爪抓取规划 | 暂不考虑夹爪 |
| YOLO 分类与语义分割 | demo 阶段纯几何分割够用，且不依赖搭档进度 |
| 运动规划 / MoveIt | 控制组的活 |
| 点云配准、SLAM 建图 | 比赛用不上 |
| C++ / PCL 重写 | demo 阶段 Python，跑通之后再翻译 |
| 多目标最优抓取顺序 | 后置阶段再说 |
| 机械臂闭环吸取 | 当前阻塞，见 1.2 |

## 二、相机安装方案

> **当前状态：相机在手，缺固定支架。** 本章的正式安装等支架到位后执行。
> 现在可以用桌面三脚架或书堆临时固定（336L 底部是 ¼-20 螺纹，三脚架通用），先跑通数据链路，见阶段 S。
> 但安装参数要先定下来：它既决定合成数据的几何，也决定临时固定的摆放。合成时用的高度和倾角，应该就是将来实际安装的那组。

这一节是正式安装的方案，也是后续所有精度数字的前提。

### 2.1 336L 的物理条件

| 项 | 数值 | 对安装的含义 |
|---|---|---|
| 尺寸 | 124 × 29 × 27.7mm | **长条形**，不是方块。装腕部时横向占用 12.4cm，容易与夹具干涉 |
| 重量 | 135g | 轻，装腕部对负载影响可忽略 |
| 安装点 | 底部 ¼-20 UNC；背部 2× M4 | ¼-20 便于快速调角度，**单点约束不足**；2× M4 才能刚性锁死 |
| 接口 | USB 3.0 Type-C（数据与供电同口） | 线材质量直接决定稳定性，且**接口处不能受力** |
| 功耗 | 平均 <3W | USB 供电够，但长线要主动延长 |
| 防护 | IP65 | 机身防尘防水，**但 Type-C 接口不防水** |
| 工作温度 | -10 ~ 50℃ | 够用 |

### 2.2 三种安装形态

| | A 固定支架（eye-to-hand） | B 腕部安装（eye-in-hand） | C 双相机 |
|---|---|---|---|
| 标定 | 一次固定变换，简单 | AX=XB，需机械臂走多姿态 | 两套 |
| 遮挡 | 臂体可能挡视线 | 相机在末端，几乎不挡 | 互补 |
| 视野 | 固定，覆盖工作区 | 随臂动，末端 10cm 内仍可见 | 全局加局部 |
| 线缆 | 固定，可靠 | 随臂运动，疲劳断线 | 一固定一运动 |
| 负载与惯量 | 不影响 | 135g 影响小，但 124mm 有悬臂力矩 | — |
| 碰撞风险 | 低 | 相机暴露在末端 | 中 |
| 视觉伺服 | 不可 | **可，能显著提高吸盘对位成功率** | 可 |
| 当前可行性 | **可立即做** | **不可，标定依赖机械臂走位** | 不可 |

### 2.3 结论：当前用 A，不装腕部

三条理由，按硬度排序：

**第一，B 方案现在根本做不了。** 手眼标定要求机械臂能精确走多个已知位姿，而现在吸盘闭环都还没通。装腕部会把手眼标定和机械臂调试绑在一起，两边互相阻塞。

**第二，124mm 的长条形状对腕部不友好。** 单点 ¼-20 固定时，12.4cm 的悬臂在振动下会产生角度漂移，而角度误差会被放大到定位误差里：偏离 1° 在 0.5m 处就是 8.7mm。要刚性锁死必须用背部 2× M4 加自制转接板，这是加工件，不是当天能完成的。

**第三，A 方案当天能装好，能立刻解阻塞。** 而且线缆固定、不增负载、不碰机械臂，三个都是「不会引入新问题」的属性。

**什么时候才考虑换 B：** 需要做视觉伺服时。吸盘对位要求高，如果固定支架的精度压在 15mm 上不去，而吸盘能容忍的偏差只有 5mm，那时腕部相机加视觉伺服才是必要的。这个判断点放在第一段交付之后，不要现在决定。

### 2.4 A 方案的具体参数

**不要垂直向下装，要斜装。**

这是本节最容易被忽略的一条。垂直向下有三个问题：

1. **遮挡最严重。** 机械臂下压时，臂体正好落在相机与目标之间。
2. **法向估计最不稳。** 垂直俯视时物块上表面在图像上几乎正对相机，平面的透视梯度接近零，微小的深度噪声会让拟合出的法向大幅摆动。斜视时平面在图像上有明确的透视梯度，法向稳定得多。
3. **顶部点云退化。** 正对时顶部点的分布接近各向同性，法向对噪声敏感；斜视时反而更稳。

但斜角不能太大，因为深度误差沿视线方向，斜视时高度误差被 1/cos(θ) 放大。θ 是偏离竖直的角度：

| 偏离竖直 | 高度误差放大 | 遮挡阴影宽度（物块高 5cm） |
|---|---|---|
| 0° | 1.00 | 0（但法向不稳） |
| 20° | 1.06 | 1.8cm |
| **25°** | **1.10** | **2.3cm** |
| 35° | 1.22 | 3.5cm |
| 45° | 1.41 | 5.0cm |

**推荐偏离竖直 25°，即俯角 65°。** 这是「法向稳定」与「误差放大」之间的折中。

**安装高度 0.5–0.7m。** 依据两条：

- 覆盖范围：深度 FOV 是 H90° V65°，在高度 h 处覆盖 `2h·tan45° = 2.0h` 宽、`1.27h` 深。h = 0.5m 时约 1.0 × 0.64m，单个抓取工位够用；h = 0.7m 时约 1.4 × 0.89m。
- 精度：空间精度是相对误差，深度误差随距离平方增长。以官方 ≤0.8%@2m（即 2m 处约 16mm）外推：

| 距离 | 深度误差 |
|---|---|
| 0.3m | 约 0.4mm |
| **0.5m** | **约 1mm** |
| 0.7m | 约 2mm |
| 1.0m | 约 4mm |
| 2.0m | 约 16mm（官方值） |

这张表说明一件重要的事：**在 0.5m 处相机的深度噪声约 1mm，远小于 15mm 的标定目标。限制最终精度的不是相机，是标定和算法。** 所以不要在选型上纠结，把力气花在标定上。

**相机方位与机械臂「待机位」的夹角要大于 90°。**

这里说的是**待机位**，不是抓取姿态。抓取那一刻臂一定在物块正上方，任何相机方位都会被挡——但那一刻不需要视觉。

视觉拍照和物理抓取在时间上是分开的：

| 时刻 | 臂的状态 | 相机看到什么 | 是否需要视觉 |
|---|---|---|---|
| T0 拍照 | 在退让位 | 视线通畅，深度完整 | **需要，且只有这一刻需要** |
| T1 移动 | 挡住物块 | 被遮挡 | 不需要，坐标已经发出去了 |
| T2 下压吸附 | 压在物块上 | 完全遮挡 | 不需要 |

判断方法：站到物块正上方往下看，机械臂**待机位**在哪个方向，相机就装在相反的方向。90° 是可接受的下限，不用追求精确的 180°，「不在同一侧」就够。

**这条判据推出一个流程要求：机械臂需要一个明确的退让位。**

退让位不是可选项，是固定相机方案能成立的前提。如果臂的待机位就紧贴工位上方，相机装哪都会被挡，这条线直接失效。这个位置要和控制组一起定，写进接口文档。

代价也要说清：每次抓取多一个「退让 → 前进」的动作，节拍会变长。比赛节拍要求紧时，这个开销要提前算进去。

如果现场做不到退让位，三条退路按优先级：相机降到侧面低角度（臂在上方时，低角度仍能看到物块侧面）；相机装高并远离工位，用长焦视角压缩臂的投影；最后才是腕部安装，但那是第二段的事。

**相机可以绕光轴转 90° 来改变覆盖形状。** FOV 是非对称的（90° × 65°），长边对应 90°。如果工作区是窄长的（比如物块沿一条线排列），把长边对准那条线，覆盖效率最高。这条在装支架时顺手就能定，装完再改要重标。

### 2.5 硬件清单

| 件 | 规格要求 | 作用 |
|---|---|---|
| 主支架 | 2020 或 3030 铝型材 + 底座 | 刚性，且长度可调高度 |
| 相机转接 | 底部 ¼-20 球头云台 | 快速调角度，粗定位 |
| 角度锁定 | 背部 2× M4 加小铝板 | **锁死角度，抗振动漂移** |
| USB 线 | USB 3.0 Type-C，**带螺纹锁定或线夹固定**，长度 ≤2m | 无源线超过 2m 可靠性下降，3m 是上限 |
| 线夹 | 扎带固定座若干 | 做 strain relief，接口处零受力 |
| 定位销 | 支架底座与桌面之间（可选） | 拆装后能复位，省一次重标 |

**最容易被省掉但最不该省的是「角度锁定」。** 单靠 ¼-20 球头，相机是「能调但也能动」的状态。手持推动、机械臂碰撞、长期振动都会让它慢慢偏，而偏了不报错，只是精度悄悄变差——这种失效最难查。背部 2× M4 加一块小铝板就能锁死。

### 2.6 三个安装期的坑

**线缆直接挂在接口上。** Type-C 接口的保持力只有几牛，线自重加上机械振动，几周就会接触不良。表现是「偶尔掉线」，而掉线会被误判成驱动问题或供电问题，查一整天。做法：线在离接口 5cm 内用线夹固定到支架上，接口处零受力。

**相机装完不复位就调参。** 支架被碰过、螺丝松过，标定就失效了。对策：每次开工前用标定板复核一次，漂移超过 5mm 就重标。这一步 3 分钟，比事后排查便宜得多。

**赛场重装后忘了重标。** 比赛现场拆装是必然的。两条路：底座加定位销做到可复位，或者把重标做成 5 分钟的一键流程（ArUco 板放固定位置，脚本自动算）。后者更可靠，因为定位销也会磨损。

## 三、吸盘改变了什么

这一节是整个计划的技术前提，也是工作量能压下来的原因。

### 3.1 视觉输出从 6D 位姿降为「表面点 + 法向」

| 项 | 夹爪 | 吸盘 |
|---|---|---|
| 需要的位置 | 物体几何中心 | 表面上的可吸附点 |
| 需要的姿态 | 6D，含绕接近轴的旋转 | 只需法向，2 个自由度 |
| 姿态自由度 | 3 | 2（绕法向自由，吸盘轴对称） |
| 关键判据 | 抓取宽度、对置面平行 | 表面平整、面积够、不漏气 |
| 典型失效 | 抓偏、滑脱 | 漏气、吸盘遮挡相机 |

推论：**不需要物体位姿估计，不需要训练位姿网络，不需要 yaw 对齐。** 这条比任何优化都省时间。

### 3.2 吸盘特有的三个约束

**一、吸的是表面，不是中心。** 输出点必须落在物体朝上的表面，且以该点为中心、直径等于吸盘直径的圆盘内，要有足够多的点落在同一个平面上。

**二、吸盘会挡住相机。** 吸盘贴近目标时相机看不到目标。两条路：相机与吸盘轴线错开一个角度，或采用「看 → 抬起 → 移动 → 下压」的两段式动作。第二段交付前先走后者，不需要改机械结构。

**三、检测到不等于吸得起来。** 表面有孔、有弧度、太斜、面积小于吸盘，都会漏气。可吸性必须单独判断，不能只输出位置。

### 3.3 可吸性判据（初值，需实测调整）

| 判据 | 初值 | 依据 |
|---|---|---|
| 表面点数 | ≥ 120 点 | 吸盘直径 20mm，0.5m 处约 0.78mm/px，降采样后约 120 点 |
| 圆盘内点到拟合平面距离 < 3mm 的比例 | ≥ 80% | 平整度 |
| 法向与竖直方向夹角 | ≤ 45° | 侧吸需要末端可达，先只吸朝上的面 |
| 圆盘内深度空洞（depth = 0）比例 | ≤ 20% | 空洞即漏气 |
| 簇点数下限 | ≥ 300 点 | 太小的是飞点或噪声 |

## 四、系统链路

```
336L ──USB3──> orbbec_camera 节点 ──> /depth/image_raw
                                  ├──> /color/image_raw
                                  └──> /points（调试用，默认关闭）
                                            │
                                    抓取检测节点（内部消化原始数据）
                                    1. ROI 裁剪，限定工作区间
                                    2. 体素降采样
                                    3. RANSAC 去桌面
                                    4. 欧式聚类
                                    5. 每簇取顶面，求中心点与法向
                                    6. 可吸性打分
                                            │
                                    /grasp_targets
                                            │
                                    tf2: camera_link → base_link
                                            │
                                    控制组：移动到预吸附位 → 下压 → 吸盘
```

两个硬约定：

- **点云不进 ROS 图。** 1280×800 的 PointCloud2 约 16.4 MB/帧，30fps 近 500 MB/s，会打满 DDS 缓冲。融合节点订阅深度图、自己反投影（见 ROS2 接入方案第五节）；`/points` 只在调试时临时开启。深度图与彩色图可以进 ROS 图（本机合计约 150 MB/s，本机 DDS 扛得住），但**跨机器必须降到 640×400**。
- **视觉只给吸附点和法向。** 预吸附位（沿法向偏移的接近点）由控制组自己算，不放进接口。责任划分清楚，接口也不会随吸盘尺寸变化而改。

## 五、任务拆解

七个阶段（S、A0、A、B、C、D、E），共 34 个任务。T 编号可直接当任务卡用。

### 阶段 S 数据准备（约 8h，当前可做）

详细方案见 `数据方案-真实采集与合成数据.md`。真实数据优先，合成数据补位。

| 编号 | 任务 | 产出 | 验收 |
|---|---|---|---|
| S1 | 临时固定（桌面三脚架，336L 底部是 ¼-20 螺纹通用），录第一段 bag 并写 `meta.yaml` | bag + meta | bag 能回放，高度/倾角/物块位置有记录 |
| S2 | 看真实深度图，记录失效模式 | 失效模式清单 | 反光、飞点、边缘缺失各至少一条实测 |
| S3 | 桌面贴 50mm 网格造真值，算误差 | 真值表 + 误差数字 | 位置误差中位数有数字 |
| S4 | 写 `lab/gen_synthetic_depth.py`：光线投射 + `σ(z)=4z² mm` 噪声 + 无效值 | 生成函数 + npy | **深度差 = 物块高 × cos(倾角)** |
| S5 | 写 `fake_camera_node`：发深度图 + `camera_info` + **真值话题** | ROS 节点 | RViz 能看到点云，真值话题有数据 |
| S6 | 补齐 `multi` / `edge` / `occluded` / `holes` 四个场景 | 场景参数表 | seed 固定，能复现 |

**S1 的 `meta.yaml` 不能省。** 高度、倾角、物块位置三样必须和 bag 一起存下来。三个月后你会需要它，而且一定不记得当时怎么摆的。

**S2 是真实数据最有价值的地方。** 反光和弱纹理是这条线的头号风险，合成数据模拟不出来，只有真实数据能暴露。发现反光导致大面积丢深度时，要立刻记录，这会影响后面的方案选择。

**S4 的验收是整个合成数据部分的根基。** 深度差对不上 `高 × cos(倾角)`，说明几何算错了，后面所有误差数字都不可信。这个自检比任何单元测试都直接，先做它。

**S5 的真值必须走独立话题**（`/ground_truth_targets`），不能混进 `/grasp_targets`。混进去会变成「用真值验证真值」，误差永远为 0。

### 阶段 A 数据通路（约 10h，相机在手，当前可做）

| 编号 | 任务 | 产出 | 验收 |
|---|---|---|---|
| A1 | 相机接入容器：`--privileged -v /dev/bus/usb`，宿主与容器内 `lsusb` 都能看到 `2bc5` | 可复现的启动命令 | 容器内能取流 |

### 阶段 B 单目标检测（约 14h）

| 编号 | 任务 | 产出 | 验收 |
|---|---|---|---|
| B1 | ROI 裁剪 + 体素降采样（0.003–0.005m） | 参数化函数 | 点数降到 1/10，目标仍完整 |

| B3 | 欧式聚类，按点数排序 | 聚类函数 | 单目标场景簇数 = 1 |
| B4 | 每簇顶面拟合：取簇内最高 20% 点拟合平面，求中心与法向 | `GraspTarget` | 中心点落在物体上表面 |
| B5 | 可吸性打分（3.3 的五条） | 打分函数 | 可吸与不可吸给出明显不同的分数 |
| B6 | 输出消息 + RViz 可视化（箭头表示法向） | 节点 + RViz 配置 | 箭头与物体表面垂直 |

B4 是这一阶段最容易做错的一步：**不要用整个簇拟合平面。** 物块是立体的，整簇拟合出来的是斜的。只取顶部一层点，拟合出的才是吸附面。

消息类型建议用 `vision_msgs/Detection3DArray`：`pose` 装吸附点与朝向，`score` 装可吸性分数，`id` 装目标编号，`bbox` 装包围盒。不用自定义消息，RViz 和 rosbag 工具链直接支持。

## 六、里程碑

| 里程碑 | 时间 | 判据 |
|---|---|---|
| **M0 真实数据到手** | 第 1 周 | 相机取流正常，第一段 bag 能回放，`meta.yaml` 完整 |
| **M1 数据通路 + 真实数据上能分割** | 第 1–2 周 | 深度 ≥ 25Hz（点云关闭）；RViz 箭头落在真实物块上，失效模式有清单 |
| **M2 真实数据有误差数字（第零段交付之一）** | 第 2–3 周 | 手工真值下位置误差中位数 < 15mm |
| **M3 合成数据补位（第零段交付之二）** | 第 3 周末 | 五场景可复现（seed 固定）；合成数据位置误差中位数 < 10mm |
| M4 正式安装 | 待支架 | 覆盖范围实测，安装参数落地 |
| **M5 基座系标定（第一段交付）** | M4 之后约 1 周 | 标定板实测误差 < 15mm；重标脚本 5 分钟跑完 |
| M6 吸起第一个物块 | 待硬件解锁 | 连续 10 次 ≥ 8 次 |

**第零段（M0–M3）约 32h，按每周 9h 计约 3–4 周。** 相机在手，这一段现在就能全速推进。第一段（M4–M5）另需约 15h（A0 5h + C 10h），依赖支架到位——基座系标定在固定支架之前物理上无法完成，这是 M5 排在 M4 后面的原因。

M2 是 S、A、B 三个阶段的汇合点（数据 + 通路 + 检测），32h 的工作压不进一周，所以 M1/M2 的排期按周区间写，而不是卡某个周末。

M2 的合格线统一为真实数据 15mm、M3 为合成数据 10mm，因为**手工真值本身有 ±5–8mm 误差**。真实数据上的误差低于 10mm 时，说明算法误差已经和真值误差同量级，测不下去了。要更精确的结论只能用合成数据——这是两者分工的根本原因。

## 七、开工前必须确认的四件事

这四个答案会改任务量和代码结构，问晚了要返工。

1. **机械臂的基座位姿怎么拿。** URDF 里有，还是要把标定板放在基座原点。这决定 C2 的实现方式。**第零段可以先用一个假定的外参把链路跑通**，等真实基座位姿确定后只换矩阵。
2. **物块是什么材质、什么尺寸、几个。** 反光或透明的物块会让 336L 大面积丢深度，是这条线的头号风险。尺寸决定降采样参数与点数阈值。
3. **控制组能提供什么接口**，能不能接收位姿话题、有没有真空压力反馈。决定 D 阶段是「给坐标」还是「给轨迹」。
4. **机械臂有没有一个不遮挡工位的退让位，相机能不能装在工位侧上方。** 这两个是固定相机方案的前提。如果臂必须常驻工位上方，或者只有正上方能立支架，2.4 的方案要重新算，得走退路。

## 八、风险清单

| 风险 | 影响 | 对策 |
|---|---|---|
| 物块表面反光或透明 | 深度大面积丢失，检测直接失效 | 优先确认材质；必要时贴哑光标记或换物块；退化为 2D 框加已知高度 |
| 支架不刚性，角度漂移 | 标定静默失效，精度慢慢变差 | 背部 2× M4 锁死；每次开工前标定板复核 |
| 线缆在接口处受力 | 偶发掉线，误判成驱动问题 | strain relief，接口 5cm 内固定 |
| 相机装正上方 | 臂体遮挡 + 法向估计不稳 | 偏离竖直 25°，与臂待机位夹角 >90° |
| 机械臂待机位紧贴工位上方 | 固定相机装哪都被挡，方案失效 | 要求控制组设退让位；退一步用侧低角度；最后才是腕部 |
| 机械臂基座位姿拿不到 | M3 卡住 | 用标定板放在基座原点作为替代基准 |
| 桌面与物块颜色接近 | 纯几何靠高度仍可行，但边缘粘连 | 平面分割必须在聚类之前，顺序不能反 |
| 物体边缘有深度飞点 | 簇被撑大，中心偏移 | 统计离群点去除；中心用顶面拟合，不用簇质心 |
| 单场景调参过拟合 | 换场景就失效 | 验收必须换三个场景各测一次 |

## 十、五条执行纪律

1. **bag 和 `meta.yaml` 一起存。** 只有 bag 没有高度、倾角、物块位置，数据废掉一半——三个月后你会需要它，而且一定不记得当时怎么摆的。
2. **S4 的深度差自检不过，合成数据不能用。** 物块顶面与桌面的深度差必须等于 `高 × cos(倾角)`。几何错了，后面所有误差数字都不可信。
3. **合成数据必须加噪声和无效值。** 无噪声数据上会调出很激进的参数（比如聚类容差取 1mm），换真实数据立刻崩。
4. **B 阶段不引入 YOLO。** 一旦依赖搭档的进度，demo 就不再由你控制。纯几何分割能覆盖「桌面上有凸起物块」这个场景，够用了。
5. **每个里程碑都要落一个可复现的命令。** 一条 `ros2 launch` 或一个脚本，别人拿到仓库能跑出同样的结果。合成数据尤其要固定 `seed`，否则前后两次跑出来的误差没法对比。
