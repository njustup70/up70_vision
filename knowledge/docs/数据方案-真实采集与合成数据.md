# 数据方案：真实采集与合成数据

## 文档说明

- 当前条件：**相机在手，但没有固定支架**。能取流、能跑算法，只是位置不固定。
- 本文解决两件事：真实数据怎么取、合成数据什么时候用、两者怎么分工。
- 与 `深度相机抓取Demo项目计划书.md` 的「第零段」对应。
- 包路径以瘦身分支的 `vision/`、`ros2_ws/`、`lab/` 结构为准。
- 路径一律相对仓库根。

---

## 一、当前条件能做什么、不能做什么

先把边界划清楚，避免把「能跑」误当成「能用」。

| 能做 | 说明 |
|---|---|
| 取流、看真实深度图 | 插上 USB 3.0 就能跑，不需要支架 |
| 测真实深度噪声 | 手持或临时摆放，能测出量级 |
| 在真实数据上跑算法 | 录成 rosbag，离线反复跑 |
| 暴露真实失效模式 | 反光、飞点、弱纹理、边缘缺失 |
| 手工测量真值 | 用卷尺和标记点，见第三节 |
| 输出消息、RViz 可视化 | 与最终形态完全一致 |

| 不能做 | 原因 | 什么时候能 |
|---|---|---|
| 手眼标定 | 相机位置会动，标定立刻失效 | 有固定支架后 |
| 严格可重复的 A/B 对比 | 每次摆位不同 | 有固定支架后 |
| 覆盖范围实测 | 位置不固定，量出来没意义 | 有固定支架后 |

**结论：没有支架不等于没有数据。** 真实数据现在就能取，而且它是唯一能暴露真实失效模式的东西。

## 二、临时固定：不需要正式支架

### 2.1 关键信息：336L 底部是 ¼-20 UNC

这是标准相机三脚架螺纹。**任何手机三脚架、桌面三脚架、云台，直接拧上去就能用。**

所以「没有支架」的实际含义是「没有专门的铝型材支架」，而不是「没法固定」。几十块钱的桌面三脚架就能解决。

### 2.2 四种办法，按成本排序

| 办法 | 成本 | 能调什么 | 适用 |
|---|---|---|---|
| **桌面三脚架 / 手机三脚架** | 几十元 | 高度、俯仰、方位，全都能调 | **首选** |
| 书堆 + 橡皮筋 / 长尾夹 | 零 | 只能调高度，角度靠塞纸片 | 临时验证 |
| 纸箱挖槽 + 泡沫垫 | 零 | 能粗略调角度 | 需要 25° 倾角时 |
| 借用现有铝型材 / 机械臂支架 | 零 | 看现有条件 | 有条件时最好 |

### 2.3 判据不是「装得多准」，是「一次实验内不动」

现在不需要追求精确安装。**只要保证一次实验（录一段 bag）内相机不动**，数据就有意义。

精确安装（高度 0.5–0.7m、偏离竖直 25°、方位夹角 >90°）等有正式支架再做。这些参数现在只影响数据质量，不影响算法对错。

## 三、真实数据怎么取，怎么造真值

### 3.1 录制

```bash
ros2 bag record -o bags/2026-10-23_single \
  /camera/depth/image_raw \
  /camera/depth/camera_info \
  /camera/color/image_raw
```

**录的时候必须同时记下三件事**，否则数据废掉一半：

1. **相机高度**（卷尺量，误差 ±1cm 可接受）
2. **倾角**（手机水平仪 App 贴在相机上量，或目测）
3. **物块位置**（在桌面上贴标记点，见下）

这些写在一个 `bags/2026-10-23_single/meta.yaml` 里，和 bag 放一起。**三个月后你会需要它，而且一定不记得。**

### 3.2 手工造真值：这是真实数据最有价值的用法

真实数据最大的问题是没真值。但有办法：

**做法**：桌面上贴坐标纸，或用胶带画出 50mm 网格。物块放在网格交点上，位置就已知了。配合已知的相机高度和倾角，物块在相机系的坐标可以算出来。

**精度**：物块摆放 ±2mm，高度测量 ±1cm 带来的深度误差约 1%，在 0.5m 处约 5mm。**综合真值精度约 ±5–8mm**，足够验证「算法误差是 10mm 还是 50mm」这个量级判断。

**这比合成数据更有说服力**，因为数据本身是真实的——反光、飞点、边缘缺失全都真实存在。合成数据只能验证算法逻辑，验证不了「真实场景下会不会崩」。

### 3.3 采集时要覆盖的五种情况

不要只拍一个理想场景。真实数据的价值在于暴露问题：

| 情况 | 怎么摆 | 看什么 |
|---|---|---|
| 理想 | 哑光物块、均匀光照、居中 | 基准精度 |
| 反光 | 光滑塑料盒、有顶灯直射 | 深度是否大面积缺失 |
| 弱纹理 | 白纸、纯色物块 | 主动 IR 点阵能否补上纹理 |
| 边缘 | 物块贴着画面边界 | D2C 对齐后边缘是否无深度 |
| 遮挡 | 两个物块叠放 | 顶面拟合是否取错 |

**反光和弱纹理这两个一定要拍**，它们是这条线的头号风险，合成数据模拟不出来。

## 四、真实数据与合成数据的分工

两者回答的问题不同，不能互相替代。

| | 真实数据 | 合成数据 |
|---|---|---|
| 回答「能不能用」 | 能 | 不能（太干净） |
| 回答「误差多少」 | 需要手工真值，精度 ±5–8mm | 能，真值精确 |
| 暴露反光、飞点、弱纹理 | 能 | 不能 |
| 可重复对比（改代码前后） | 不能（摆位会变） | 能（固定 seed） |
| 参数批量扫描 | 不能（太慢） | 能（几分钟几百组） |
| 覆盖极端场景（holes、edge） | 难摆 | 容易 |

**一句话分工：真实数据定方向，合成数据量误差。**

- 真实数据告诉你「这个参数在现实中会崩」→ 你回去改算法。
- 合成数据告诉你「改完之后误差从 25mm 降到 8mm」→ 你确认改对了。

只做真实数据：改完不知道有没有变好，因为没有可对比的基准。
只做合成数据：参数调得很漂亮，接真实相机立刻崩。

**两个都要，顺序是先真实后合成。** 先看真实数据长什么样，才知道合成数据该模拟什么。

## 五、合成深度图怎么生成

### 5.1 几何：向量化光线投射

640×400 是 25.6 万条射线，numpy 向量化一次约 50–100ms，生成一次存 `.npy`，不需要实时。

四步：

1. **像素方向向量**：`d_cam = normalize([(u-cx)/fx, (v-cy)/fy, 1])`，得到 (H, W, 3)。
2. **转到世界系**：`d_world = d_cam @ R.T`，`R` 由 `tilt_deg` 绕 x 轴旋转得到。
3. **与桌面求交**：桌面是 `z=0` 平面，`t = -o_z / d_z`。
4. **与物块求交**：物块是轴对齐立方体，用 slab method 求进入距离 `t_enter`。取 `min(t_plane, t_enter)`。

**深度值 = `t × d_z_cam × 1000`，不是 `t × 1000`。** `d_z_cam` 是单位方向向量在相机系 z 轴上的分量（`d_z_cam = 1 / ‖[(u-cx)/fx, (v-cy)/fy, 1]‖`）。真实 336L 输出的是沿光轴的 z 深度，不是斜距；90°×65° 的宽 FOV 下，两者在画面边缘可差 20% 以上。生成器若把 `t` 直接当深度，S4 的「深度差 = 高 × cos(倾角)」自检必然失败——这条自检恰好就是用来抓这个错的。

### 5.2 噪声：按官方精度指标外推

以官方 ≤0.8%@2m（2m 处 16mm）为锚点，深度误差随距离平方增长：

```
σ(z) = 16 mm × (z / 2m)²  =  4 z²  [mm，z 单位米]
```

| 距离 | σ |
|---|---|
| 0.3m | 0.36 mm |
| 0.5m | 1.0 mm |
| 1.0m | 4.0 mm |
| 2.0m | 16 mm |

**加噪是为了让参数有裕量。** 无噪声数据上会调出很激进的参数（聚类容差取 1mm），换真实数据立刻崩。

**这个公式要用真实数据校准。** 相机在手，A4 任务（噪声实测）现在就能做，测出来的数字如果和这张表差很多，说明公式的锚点不对，要改。

### 5.3 无效值：不能忘

真实深度图在三种地方是 0：超量程、弱纹理、物体边缘的遮挡阴影。合成数据至少要模拟后两种：

- **遮挡阴影**：物块背向相机的一侧，射线被物块挡住打不到桌面，这些像素应为 0。在 ray casting 里，`t_enter` 存在但射线先打到桌面时，说明被遮挡，置 0。**这个判断要写对，否则合成数据比真实数据"干净"。**
- **边缘飞点**：物块轮廓一圈随机置 0，比例约 5–10%。

## 六、假相机节点

### 6.1 结构

```
ros2_ws/src/vision_depth/vision_depth/fake_camera_node.py   ROS 节点，定时发合成数据
    ├─> /camera/depth/image_raw       sensor_msgs/Image (16UC1)
    ├─> /camera/depth/camera_info     sensor_msgs/CameraInfo
    └─> /ground_truth_targets         vision_msgs/Detection3DArray（真值）
```

**真值单独发一个话题**，绝不混进 `/grasp_targets`。混进去会变成「用真值验证真值」，误差永远是 0。

`fake_camera_node` 不发 `/detections_2d`——第零段的 `fuse_node` 走纯几何模式（`use_2d_dets:=false`），不需要 2D 框。

### 6.2 节点参数

| 参数 | 作用 | 默认 |
|---|---|---|
| `height_m` | 相机高度 | 0.6 |
| `tilt_deg` | 偏离竖直角度 | 25.0 |
| `scene` | 场景名，见第七节 | `single` |
| `noise` | 是否加噪声 | `true` |
| `fps` | 发布频率 | 15 |
| `seed` | 随机种子 | 0 |

`seed` 固定，保证每次跑出来的数据一样。**这是能对比前后改动的前提。**

## 七、五个场景，每个对应一类失效模式

| 场景 | 内容 | 验证什么 |
|---|---|---|
| `single` | 一个 50mm 立方体在画面中心 | 基准精度 |
| `multi` | 三个物块，间隙 30mm | 聚类能否分开 |
| `edge` | 物块在画面边缘 | D2C 边缘无深度、ROI 是否切掉目标 |
| `occluded` | 两个物块部分重叠 | 顶面拟合是否只取到上表面 |
| `holes` | 物块表面 30% 随机置 0 | 可吸性判分能否拒绝 |

`holes` 最容易忽略，但它对应真实的反光物块。**如果算法在这里给高分，说明可吸性判分形同虚设**——而那正是这条线的头号风险。

## 八、误差怎么算

三个指标，都报中位数和 P95，不要只报平均值（平均值会被少量大误差掩盖）。

| 指标 | 算法 | 合格线 |
|---|---|---|
| 位置误差 | `‖估计中心 − 真值中心‖` | 真实数据中位数 < 15mm；合成数据中位数 < 10mm、P95 < 20mm |
| 法向误差 | `acos(估计法向 · 真值法向)` 转角度 | 中位数 < 5° |
| 漏检率 | 该检出的目标没检出 | < 5% |

真实数据的真值精度约 ±5–8mm，所以**真实数据上的误差低于 10mm 时，说明算法误差已经和真值误差同量级，测不下去了**。要更精确的结论，只能用合成数据。

## 九、落地顺序：先真实后合成

| 步骤 | 动作 | 验收 |
|---|---|---|
| 1 | 相机接上，跑通取流 | `ros2 topic hz` 深度 ≥ 25Hz |
| 2 | 临时固定（桌面三脚架），录第一段 bag，写 `meta.yaml` | bag 能回放，`ros2 bag info` 时长和帧数对 |
| 3 | 看真实深度图，记录失效模式 | 列出反光、飞点、边缘缺失各出现在哪 |
| 4 | 在 bag 上跑算法，看能否分割出物块 | RViz 里箭头落在物块上 |
| 5 | 桌面贴网格，手工造真值，算误差 | 位置误差中位数有数字 |
| 6 | 写 `lab/gen_synthetic_depth.py`，补真实数据拍不出的场景 | 深度差自检通过（见下） |
| 7 | 写 `fake_camera_node`，固定 seed | RViz 能看到点云，真值话题有数据 |
| 8 | 用合成数据做参数扫描，用真实数据验收 | 参数在两边都不崩 |

**第 6 步的自检是根基**：物块顶面与桌面的深度差必须等于 `物块高 × cos(倾角)`。对不上说明几何算错了，后面所有误差数字都不可信。

**第 8 步是这套流程的关键。** 在合成数据上调参数，在真实数据上验收。只在一边调好的参数不算数。

## 十、这套东西的长期价值

即使有了正式支架，这两套数据也不要丢。

**真实 bag 的三个用途**：回归测试的真实基准（改完算法回放对比）、给新人的教学样本、赛场出问题时的事故现场记录。

**合成数据的三个用途**：CI 里的回归断言（固定 seed + 误差阈值）、参数批量扫描、给控制组的假数据源（他们不用等相机）。

**所以 `fake_camera_node` 和 `bags/` 都不是临时脚手架。** 相机装好之后不要删。

---

## 十一、一句话

**有相机就先吃真实数据，它会告诉你真实世界长什么样；合成数据用来量化改进幅度和覆盖拍不出来的场景。** 两者分工不同，谁也不能替代谁。
