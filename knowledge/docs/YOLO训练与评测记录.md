## 1. 数据集与实验条件

### 1.1 数据集版本与规模

| 项 | 值 |
|---|---|
| 版本 | `yolo-real-v2`（2026-10-30：v1 的 120 张 + 新采远景 128 张） |
| 真图总数 | **248 张**（1280×1024，JPEG） |
| 真图划分 | train **176** / val **36** / test **36**（按"连拍串"整段分配，见 1.3） |
| 真图实例数 | train 687（block 372 / top 315）、val 143（85/58）、test 162（81/81） |
| 合成数据 | 300 张（train 240 / val 60），`block` 267 / `top` 183 |
| 混合训练集 | 合成 300 + 真图 212 = **416 张**（`data/yolo_mix3`） |

> 类别定义：`block` = 350 mm 单色方块，`top` = 200 mm 半红半蓝塔顶（红蓝**上下叠放**）。
> **颜色不进类别**——红/蓝由 HSV 判（`configs/color_thresholds.yaml`），塔顶取"上半块"判色。

### 1.2 数据来源（拍摄条件）

| 项 | 值 |
|---|---|
| 相机 | 海康 MV-CU013-A0UC（USB3 Vision，MVS SDK），1280×1024 |
| 场景 | 办公室走廊 + 地面黑白地贴；白墙、玻璃门、门框、反光地面均在画面内 |
| 距离 | 约 0.4–2.5 m（含近景大目标与远景小目标） |
| 光照 | 白天自然光 + 室内灯；白墙常过曝，**曝光按场景取 6–28 ms** |
| 角度 | 俯视、平视、斜视 30–60°，含红蓝块叠放/并排/遮挡 |
| 采集批次 | 6 组：g1 正对 / g2 塔顶 / g3 斜视 / g4 叠放 / g5 距离梯度 / **g6 远景（1.5–2.5 m，塔 40–80 px）** |
| 真实机器人环境 | **无**（实验室地面摆放，非比赛场地） |

### 1.3 数据划分方法（防泄漏）

- **按"连拍串"整段分配**：32×32 灰度余弦相似度 >0.90 的帧视为同一条连拍，整串只进一个划分
  （`lab/split_dataset.py`）。随机切会让同一姿势的帧跨集，val/test 出现近重复 → mAP 虚高；
- 按来源分组分层：6 个采集组各自出 val/test，避免某组完全缺席；
- 自检（每次划分都打印）：val/test 与 train 的最大相似度 = 0.884 / 0.907，**>0.95 的帧 0 张**；
- 图片 MD5 交集检查：train∩test、train∩val、val∩test 均为 **0 张**；
- 随机种子 20261030，划分结果落在 `data/yolo_real_v2/`。

### 1.4 模型与训练

| 项 | 值 |
|---|---|
| 模型 | **YOLOv8n**（ultralytics 8.4.x） |
| 预训练权重 | `knowledge/models/yolov8n.pt`（COCO） |
| 输入尺寸 | 640×640（**ONNX 静态导出只支持 640**，320/480 会崩） |
| 训练轮数 | 40 epoch，batch 8，CPU，workers 2，optimizer auto，lr0 0.01（数据量 416 张，约 50 分钟） |
| 数据增强 | ultralytics 默认：mosaic 1.0、translate 0.1、scale 0.5、fliplr 0.5、HSV h/s/v = 0.015/0.7/0.4 |
| 离线增强 | `lab/augment_dataset.py`（翻转/90–270° 旋转/缩放平移 + 亮度扰动，**不改色相**）；本轮训练**未启用** |

### 1.5 评价设置

| 项 | 值 |
|---|---|
| 测试集 | `data/yolo_real_v2` 的 `test` 划分，**36 张 / 162 个框** |
| 置信度阈值（报告中主值） | **0.45**（与部署默认 `detector.yolo.conf` 一致） |
| NMS IoU | 0.45（部署）；训练时 ultralytics 内部 val 用 0.7 |
| 匹配 IoU | 0.5（mAP@0.5）、0.5:0.95（mAP@0.5:0.95） |
| 类别匹配 | 必须类别一致才算 TP（不跨类匹配） |

### 1.6 运行环境

| 项 | 值 |
|---|---|
| 训练 | 本机 CPU（Intel i7 级别，无 GPU），`device=cpu` |
| 推理 | `cv2.dnn` + ONNX（FP32），1280×1024 输入缩放至 640 |
| 推理耗时 | **≈43 ms/帧**（CPU，单线程 dnn；约 23 fps） |
| 依赖 | opencv 4.11（宿主 venv）/ 4.14（容器）均可，**不需要 torch** 推理 |

## 2. 识别效果指标

### 2.1 总体（真图 test，36 张 / 162 框）

| 指标 | 值 |
|---|---|
| Precision | **0.918** |
| Recall | **0.931** |
| mAP@0.5 | **0.957** |
| mAP@0.5:0.95 | **0.850** |
| F1（固定工作点 conf 0.45、IoU 0.5，工具复算） | **0.951** |

### 2.2 每类（真图 test）

| 类别 | 实例数 | P | R | mAP@0.5 | mAP@0.5:0.95 |
|---|---|---|---|---|---|
| `block` | 81 | 0.943 | 0.926 | 0.945 | 0.861 |
| `top` | 81 | 0.894 | 0.936 | 0.969 | 0.838 |

> 相比 v1，`top` 召回从 0.741 提到 0.936 —— 主因是补了远景数据 + 修正了"叠放被标成一框"的错误标签。

### 2.3 错误分类（`lab/eval_errors.py`，IoU 0.5、类别须一致）

| 模型 | conf | TP | FP | FN | P | R | F1 | 重复框 | **合并** | 类别错 |
|---|---|---|---|---|---|---|---|---|---|---|
| mix2（v1 模型） | 0.45 | 116 | 12 | 46 | 0.906 | 0.716 | 0.800 | 0 | **18** | 3 |
| **mix3（v2 模型）** | 0.45 | 155 | 9 | 7 | 0.945 | 0.957 | 0.951 | 0 | **4** | 3 |

**合并 = 一个预测框里装着 ≥2 个真值框中心**（"两块看成一个"）。这是本轮的主攻目标，18 → 4。

### 2.4 对照实验（同划分、同评价口径）

| 训练数据 | mAP@0.5 | 备注 |
|---|---|---|
| 只用合成 300 | 0.730 | v1 test（17 张）上的历史数，口径与 v2 不同，仅作趋势参考 |
| 合成 + 自动标注（3 类） | 0.659 | 错误类别定义，已废弃 |
| 合成 + 人工标注（2 类，v1 数据） | 0.874 | v1 test（17 张） |
| **合成 + 人工标注（2 类，v2 数据 + 128 张远景）** | **0.957** | v2 test（36 张），本版 |

### 2.5 本轮最重要的一条教训

**预标注的"合并框"会教坏模型。**

新采的 128 张远景图用 v1 模型预标注，其中 **85 个框（16%）把上下两块叠放标成了一个竖长框**（h/w ≈ 1.55）。
直接拿它训练后，模型在 v2 test 上的合并次数是 **18 次**（比不补数据的 v1 还差）。
把竖长框按中线拆成两个（540 → 624 个框）后重训，合并降到 **4 次**，mAP@0.5 从 0.722 提到 0.957。

> 结论：**补数据之前必须先验证预标注的质量**。判据：`block` 框的高宽比 >1.35 基本就是"两块被合并"。

### 2.6 已知问题

| 问题 | 证据 | 后续 |
|---|---|---|
| 仍有 4 次合并 | 叠放且同色、远景小目标 | 继续补远景/叠放样本，或试 960 输入 |
| 类别错 3 次 | 塔顶/方块在极端视角混淆 | 增加该类样本 |
| 环境误检偶发 | test 上 FP 9 | 补空场景负样本（比赛场地固定后再拍） |
| 暗光下退化 | 真机 20:50 关灯测试亮度 43，只检出 1 个目标 | 现场补光或提高曝光，评测时也要覆盖暗光 |

## 3. 复现命令

```bash
cd "/home/sxy/桌面/vision opencv/up70_vision-main"

# 1) 训练（数据：合成 300 + 真图 86；约 25–40 分钟 CPU）
YOLO_CONFIG_DIR=runs/.cfg ~/.venvs/yolo/bin/yolo detect train \
  model=knowledge/models/yolov8n.pt data=data/yolo_mix3/dataset.yaml \
  epochs=40 imgsz=640 batch=8 device=cpu name=mix3 exist_ok=True

# 2) 在真图 test 上评（表 2.1 / 2.2 的来源）
YOLO_CONFIG_DIR=runs/.cfg ~/.venvs/yolo/bin/yolo detect val \
  model=runs/detect/mix3/weights/best.pt data=data/yolo_real_v2/dataset.yaml \
  split=test imgsz=640 device=cpu plots=True name=mix3_eval

# 3) 导出 ONNX（运行时用，无需 torch）
PYTHONPATH=. ~/.venvs/yolo/bin/python lab/export_yolo.py \
  --weights runs/detect/mix3/weights/best.pt --out knowledge/models --name yolov8n_mix3

# 4) 部署推理（2 类 + HSV 判色）
PYTHONPATH=. ~/.venvs/vision/bin/python -m vision run \
  --set detector.name=yolo --set detector.yolo.weights=knowledge/models/yolov8n_mix3.onnx
```

产物位置：权重 `runs/detect/mix3/weights/`，曲线与混淆矩阵 `runs/detect/mix3_eval/`，
模型 `knowledge/models/yolov8n_mix3.onnx`（+ 同名 `.names.json`，两个文件必须一起拷）。
