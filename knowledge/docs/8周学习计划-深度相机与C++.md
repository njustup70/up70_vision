# 8 周学习计划：深度相机与 C++

> 起点：深度相机零基础，C++ 有算法竞赛底子（语法、STL、指针基本概念在），没碰过工程化与第三方库。
> 时间预算：每周 9 小时，8 周 72 小时，另留 8 小时缓冲。
> 分工前提：搭档负责 YOLO 一侧，本计划只覆盖深度相机一侧。
> 定位：本计划是「能力线」；交付线以《深度相机抓取Demo项目计划书》为准。Week 5–8 的 C++ 练习包独立命名 `vision_depth_cpp`，与交付线的 Python 包 `vision_depth` 不同名、不混用、不部署；其排期服从计划书「M3 之后」的约束。
> 环境前提：全部工作在 Ubuntu 22.04 + ROS 2 Humble 内完成，主环境是战队镜像 `up70docker/rc2027:yolo-gpu-ros`。
> 文中路径一律相对仓库根；原型脚本统一放 `lab/`。

| 编译链 | g++ / cmake / pkg-config / build-essential | Week 5 起要用 |

### 镜像里没有的，本计划要处理

| 缺什么 | 影响 | 处理 |
|---|---|---|
| PCL（`libpcl-dev` 等） | Week 5 起 C++ 点云编不了 | 改 Dockerfile 加三行，体积约 +1.5GB |
| Orbbec SDK / `orbbec_camera` | Week 1 相机接不进来 | Week 1 在容器内装 |
| udev 规则 | 容器内没有 udev daemon | 用 `--privileged` 绕过 |

### 三个必须提前知道的坑

**第一，`--device=/dev/video0` 对 336L 无效。**

`Dockerfile-vision-ros2-gpu` 头部的运行示例写的是 `--device=/dev/video0 --group-add video`，那是给普通 UVC 摄像头用的。336L 走 libusb 直接访问，不是 V4L2 设备，容器里根本没有 `/dev/video0` 这个节点。正确的起法：

```bash
docker run -it --rm \
  --gpus all --network host --ipc host \
  --privileged \
  -v /dev/bus/usb:/dev/bus/usb \
  -v /tmp/.X11-unix:/tmp/.X11-unix -e DISPLAY \
  -v "$(pwd)":/workspace \
  up70docker/rc2027:yolo-gpu-ros
```

`--privileged` 是绕过「容器内没有 udev daemon」最省事的办法。比赛环境不涉及多租户，这个取舍可以接受。

**第二，`v4l2-ctl` 也查不到 336L。** 同理，它不是 V4L2 设备。查设备用 `lsusb`，应该能看到 Orbbec 的 `2bc5:xxxx`。镜像里装了 `v4l-utils` 是给普通摄像头准备的，本线用不上。

**第三，Docker 内相机不一定通。** 如果 `--privileged` 加 `-v /dev/bus/usb` 之后 SDK 仍枚举不到设备，说明这台机器上容器访问 USB 有问题。此时启用混合模式：**相机取流走原生 Ubuntu，算法与 C++ 编译仍在 Docker 里**，两边用 rosbag 或挂载目录交换数据。这个模式可接受，不要为它耗超过两天。

## 一、结论先行

**第一，前 4 周不碰 C++，后 4 周才进。** 理由不是怕难，是顺序问题：C++ 环境搭建（CMake、ament、PCL 链接）是最容易卡住的地方，如果第一周就卡在这里，你对相机本身的理解会一起停摆。先用 Python 把数据语义和算法吃透，C++ 阶段只是换语言重写已验证的东西。

**第二，8 周里只有 6 件事需要动手做透，其余全部是查文档。** 这 6 件事是：反投影、滤波链顺序、参数标定、噪声实测、C++ 构建链、2D-3D 融合。剩下的类名、函数签名、文件格式，忘了就查，不值得背。

**第三，最大风险不在算法，在 C++ 的「工程化」这一层。** 你竞赛写的 C++ 是单文件、无依赖、只用标准库；这条线要写的是多文件、有依赖、有构建系统的代码。这两者的差距不是语法，是四个新东西（见第七节）。第五周之前必须把这块补上，否则后面三周都在跟链接错误搏斗。

## 二、知识分层：什么要学透，什么只要查得到

判断标准只有一条：**这个知识忘了之后，能不能在 5 分钟内查到？**

- 能查到（类名、参数名、函数签名、字段含义）→ **只需记忆**，用的时候查，不花时间背。
- 查不到（为什么这个顺序、这个参数怎么定、这个现象说明什么）→ **重点掌握**，必须动手做出来。

### 必须动手做透的六件事

| 项 | 为什么必须动手 | 达标动作 |
|---|---|---|
| 反投影公式与坐标系 | 整条线的地基，写错符号后面全错 | 不看资料手写公式，并做一次地面高度自检 |
| 滤波链的顺序 | 顺序错了结果错但不报错，最难查 | 说出为什么聚类必须在平面分割之后 |
| 三个关键参数的定法 | 参数靠实测，抄教程必错 | 给出 `leaf_size`、`distance_threshold`、`cluster_tolerance` 三个值的实测依据 |
| 深度噪声实测 | 你唯一能自证「做完了」的东西 | 输出 0.5/1/2/4m 四点的噪声数字与曲线 |
| C++ 构建链 | 最大风险，卡住就是几周 | 从零建一个能编译、能链接 PCL 的 ROS2 包 |
| 2D-3D 融合 | 这条线唯一的对外接口 | 给一个目标输出机器人系坐标并报误差中位数与 P95 |

### 只需记忆，用的时候查

| 内容 | 查哪里 |
|---|---|
| PCL 各类的名字与方法（`pcl::VoxelGrid`、`setLeafSize`…） | PCL 官方 API 文档 |
| PCD 文件头字段（`FIELDS`、`WIDTH`、`POINT_STEP`…） | PCL 文档或 `pcl_viewer` 直接看 |
| `sensor_msgs/PointCloud2` 的字段定义 | ROS2 消息文档 |
| Gemini 336L 的全部参数 | 已整理在《深度相机融合学习方案》型号节（该文档未入库时以官方规格书为准） |
| `cv2.calibrateCamera`、`cv2.solvePnP` 的参数顺序 | OpenCV 文档 |
| CMakeLists 的模板写法 | 照抄仓库里已有的包 |

### 明确不学

- **PCL 的 `features` 模块**，除 FPFH 之外全部不碰。
- **PCL 的 `surface` 模块**（移动最小二乘、凹包、泊松重建）。
- **`registration` 里的其他算法**：只学 ICP 一种。
- **点云深度学习**（PointNet++、VoxelNet、PointPillars）。
- **SLAM 与建图**（LOAM、Cartographer、FAST-LIO）。
- **C++ 模板元编程、智能指针进阶用法**。
- **ROS2 的 action、lifecycle node、composition**。
- **Open3D 的可视化与 GUI**，可视化统一用 RViz。

### Week 1：把相机接进来

#### Day 1 · 周一 · 1.5h · 确认容器能看到 336L

**任务**：先把相机在容器里的可见性解决掉，这是整条路的第一道门。分三步，每步都要验证：

1. 宿主上 `lsusb | grep -i orbbec`，确认系统认到设备（应是 `2bc5:xxxx`）。
2. 用 `--privileged -v /dev/bus/usb:/dev/bus/usb` 起容器，容器内再 `lsusb`，确认设备透进来了。
3. 容器内装 `pyorbbecsdk`，跑官方示例，看到深度图和彩色图。

**完成标志**：容器内 Python 脚本打印出深度图 shape（1280×800 或 640×400），彩色图能显示在窗口里。

**卡住怎么办**：宿主 `lsusb` 看不到设备，先换线换口，确认插的是 USB 3.0；容器内看不到，试 `--device=/dev/bus/usb/001/00X`（总线号用 `lsusb -t` 查）；还是不行，直接启用混合模式——相机在原生 Ubuntu 跑，算法在 Docker 里跑，别在这上面耗。

#### Day 3 · 周三 · 1.5h · 数值范围确认

**任务**：在能出图的那个环境里，存一帧深度图为 `.npy`，检查数值分布。打印最小值、最大值、唯一值数量，统计 0 值像素占比，看正对 0.5m 处平面时深度值是多少。

**完成标志**：能说出「深度值 500 对应多少米」，并给出 0 值像素占比。

**为什么这天重要**：`depth_scale` 搞错，后面所有距离都会错一个量级，而且不会报错。

#### Day 5 · 周五 · 1.5h · 定下 Docker 与原生怎么分工

**任务**：把 Day 1 的结果落成一个明确的运行方式，写进仓库的 README 或 `docs/env.md`，三件事要定死：

- 相机取流在哪跑（容器 / 原生）
- 算法与编译在哪跑
- 两边怎么交换数据（rosbag 挂载目录 / 直接跑在同一个环境）

**完成标志**：写出三条结论，别人照着能复现你的环境。

**卡住怎么办**：如果 Day 1 的容器路线没通，这天就把原生 Ubuntu 的 ROS 2 与 `orbbec_camera` 装好，容器只用来编译 C++。

#### Day 6 · 周六 · 4.5h · orbbec_camera 跑通

**任务**：

- 上午（2.5h）：装 `orbbec_camera` ROS2 包，`colcon build`，跑 launch 文件。建议在挂载出来的 workspace 里编译，不要重打镜像，重打一次至少二十分钟。
- 下午（2h）：`ros2 topic hz` 测三个话题的频率；RViz 里加 Image 和 PointCloud2 显示。

**完成标志**：深度 ≥25Hz、彩色 ≥25Hz、点云有数据；RViz 里能看到自己。

**卡住怎么办**：launch 报找不到设备，先跑包里的 `install_udev_rules.sh` 再重新插拔；频率太低就把分辨率降到 640×400 再测。

#### Day 7 · 周日 · 缓冲

提前完成的话，录一段 30 秒 rosbag：10 秒静止、10 秒手在镜头前移动、10 秒无目标。后面几周都要用它。

**Week 1 验收**：拔掉相机再插上能重连；三个话题频率稳定；有一段可回放的 rosbag。

### Week 5：第一次让 C++ 编译通过

这一周是全程的分界点。前四天的目标是「编译通过」，不是「功能完整」。

#### Day 29 · 周一 · 1.5h · 给镜像补上 PCL

**任务**：战队镜像里**没有 PCL**，这是 Week 5 的第一件正事。两个选择：

- 改 `Dockerfile-vision-ros2-gpu` 的 §2，在 apt 那行加 `libpcl-dev libeigen3-dev libboost-all-dev`，重打镜像（体积约 +1.5GB）。
- 在运行中的容器里 `apt install`，快但重启就没了。

## 七、竞赛 C++ 到工程 C++：四个新东西

你有算法竞赛底子，语法、STL、指针都不用再学。但工程 C++ 有四个竞赛里不存在的东西，这四样才是 Week 5 真正要过的关。

**第一，构建系统。** 竞赛是 `g++ main.cpp -o main`，工程是 CMake：声明依赖、找包、生成构建文件、编译、安装。要理解 `find_package` 在做什么（找 `PCLConfig.cmake`）、`target_link_libraries` 为什么顺序有讲究、`ament_target_dependencies` 和前者什么关系。

**第二，依赖管理。** 竞赛只用标准库，工程要引入 PCL、Eigen、ROS2 的消息包。依赖要在两个地方声明：`package.xml`（给 ROS 的包管理器看）和 `CMakeLists.txt`（给编译器看）。两边不一致就会报「找不到头文件」或「未定义引用」。

**第三，多文件组织。** 竞赛是单文件，工程是头文件加源文件：声明放 `.h`、实现放 `.cpp`、编译单元之间靠链接合并。要理解为什么头文件要写 include guard、为什么模板实现要放头文件、`namespace` 怎么用。

**第四，第三方库的 API 风格。** 竞赛用标准库，接口是函数式的（`sort(v.begin(), v.end())`）。PCL 是对象式的：先建对象、用 setter 配参数、再调用执行方法、结果通过指针参数返回。这个风格不熟会写得很别扭，但写三个滤波器就习惯了。

**这四条都不需要专门学，在 Week 5 建包的过程中自然会碰到。** 碰到的时候查清楚，比提前看教程有效。

| 风险 | 出现时间 | 降级方案 |
|---|---|---|
| 容器内看不到 336L | Day 1 | 试 `--device=/dev/bus/usb/00X/00Y`；仍不行启用混合模式：相机在原生跑，算法在容器跑 |
