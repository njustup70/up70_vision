## 0. 先建立心智模型（比背命令重要）

**做什么**：图像进来 → 找目标（ArUco / YOLO / 判色）→ 算位姿 → 画图落盘。
没有相机也能跑：`input.source=synthetic` 会自己造图，这是新人第一个能跑通的闭环。

**3D 抓取是另一条线**：算法在 `vision/depth/`（纯 Python，可 pytest），ROS 2 外壳在
`ros2_ws/src/vision_depth/`，由深度侧同学维护；只做 2D 的话可以先完全忽略它。

**三层结构，按"文件寿命"分，规矩不同**：

| 目录 | 放什么 | 规矩 |
|---|---|---|
| `vision/` | 运行时代码 | 要 import、要测、要评审；**有架构约束**（功能包互不 import、不碰 cli/config、不 import lab） |
| `lab/` | 一次性工具（造图、核对、标定、导出） | **零约束**：可以长、可以互相 import、可以不写测试 |
| `knowledge/` | 文档、棋盘、权重说明、截图 | 只放数据与文档，不放可执行代码 |

`configs/` 留根（lab 与 vision 都要读）；`tests/` 放回归与夹具；`output/`（运行产物）、`data/`（数据集）、`runs/`（训练产物）都是生成物，不进库。

**依赖方向单向**：`config` / `types` ← 功能包（`aruco` `yolo`）← `sources` ← `cli` ← `__main__`；
`api.py` 是给外部（lab、测试、将来的 ROS 节点）的库门面。**改错方向，`tests/test_architecture.py` 会红。**

## 1. 跑通（三分钟，之后每次改代码前先跑一遍）

```bash
git clone <仓库地址> && cd up70_vision-main
docker compose -f .devcontainer/docker-compose.yml build
docker compose -f .devcontainer/docker-compose.yml run --rm vision python -m vision doctor
docker compose -f .devcontainer/docker-compose.yml run --rm vision python -m vision demo
docker compose -f .devcontainer/docker-compose.yml run --rm vision python -m vision run --set input.source=synthetic
```

期望：`doctor` 末行「结果：全部通过」、`demo` 末行 `PASS`、`run` 打印 **18 个色块、判色 18/18** 且退出码 0，
`output/demo/` 里出现叠加图 / `results.json` / `detections.csv` / `summary.json`。

后续可直接运行对应检查。以上是共用 Humble 环境；海康通过 `WITH_MVS=1` 加装 SDK，见[共用相机容器](../../.devcontainer/README.md)。不想用 Docker：`pip install -e .` 后同样命令（容器外执行时不加 docker 前缀）。

## 2. 改代码的四条规矩（新人最容易在这里浪费一天）

1. **入口归属先判断**：新功能**默认进 `lab/`**（直接 `python lab/xxx.py`）。
   只有"一年用 ≥3 次"的才做成 `python -m vision <子命令>`，并同步在 `vision/__main__.py` 登记——
   现在主入口只有 6 条，`scripts/` 目录已删除，CI 会拦住它复活。
2. **依赖方向不能反**：功能包之间互不 import；`vision/` 绝对不能 import `lab/`（否则一次性工具就删不掉了）。
   放不准就问一句："这份代码有几个使用者？" 一个→放使用者旁边；两个以上且不能互相 import→放共用层。
3. **每个模块按同一形状写**：文件头 docstring 三段（放什么 / 不放什么 / 依赖谁），行为有硬校验，
   测试断言带**具体数字**（`9/9`、`≤ 0.23 px`），不写 `assert x > 0`。规范见 `knowledge/docs/代码注释规范.md`。
4. **提交与合并**：分支名 `feat|fix|docs/<中文关键词>`；提交信息标题 ≤50 字、正文 ≤4 行（`knowledge/docs/提交信息规范.md`）；
   合并用 **squash**，合并信息写成 `<type>: 一句话 (#PR)`，**PR 作者自己按合并**。

**测试怎么跑**：共用镜像含 pytest，完整回归须在不含本地实验输出的隔离源码副本中运行 `python -m pytest tests/ -q`。部分测试会重建 `output/` 固定目录，不在原工作区运行全套。

## 3. 常见任务从哪下手

| 想做的事 | 从哪看起 / 改哪 |
|---|---|
| 看实时画面、调曝光 | 加装 MVS 后运行 `python -m vision live`；参数在 `configs/default.yaml` 的 `input.camera` |
| 换场地调颜色 | 只改 `configs/color_thresholds.yaml`；用 `python -m vision hsv-tuner` 拖着调 |
| 核对检测/位姿准不准 | `python lab/check_aruco.py`、`python -m lab.pose_check --dir <图组>`（或 `--sweep`） |
| 加一个新检测器 / 新功能 | 先在 `lab/` 里写通，再判断值不值得进 `vision/`；进的话放功能包内（见第 2 条） |
| 接 ROS 2 | 只读 `vision/api.py` 与 `vision/types.py`；契约见 `vision/docs/interface.md` |
| 标定相机 / 打印棋盘 | `lab/gen_chessboard.py` + `lab/calibrate_camera.py` |
| YOLO | 先 `lab/export_yolo.py` 导 ONNX（权重不进库），再 `--set detector.name=yolo` |

## 4. 新人最常踩的坑（会浪费一天的，按发生频率排）

| 坑 | 真相 |
|---|---|
| 相机打不开，报错也不说原因 | 它是 **USB3 Vision 不是 UVC**，`cv2.VideoCapture` 永远打不开；要 udev 权限 + MVS deb 进镜像 + 透传 `/dev/bus/usb`。且相机**独占**：MVS 客户端/调参窗口占着就打不开 |
| 容器里窗口起不来 | 宿主 X11 授权、DISPLAY 和 `/tmp/.X11-unix` 三件事（后两项 Compose 已包含）；旧镜像还会缺 `libsm6`。无显示器用 `--headless` |
| 装了 `opencv-contrib-python` 或 `-headless` | 和 `opencv-python` 顶层模块同名 `cv2`，静默覆盖，功能莫名其妙没了 |
| 尺寸填错但**不报错** | 棋盘格（23 mm）与 ArUco 码（82.5 mm）是两个东西；填错只让内参/距离按比例错，重投影误差照样很小 |
| 新 clone 跑不了位姿 | `configs/camera_calibration.yaml` 与权重都在 `.gitignore` 里：内参要自己标，权重要自己导 |
| `output/` 里找不到刚生成的图 | 批处理的图在 `--out` 指定目录（默认 `output/demo/`）；`live --headless` 的在 `output/aruco/`，文件名是 `frame_000000`，**重跑会覆盖** |
| 混用两种相机入口 | 海康用 `input.source=camera`，`live` 支持 ArUco/YOLO/判色；Gemini 真机走 ROS launch |
| 改了代码容器没变 | 代码是 bind mount 立即生效；修改依赖、SDK 或 Dockerfile 后重建；Gemini 的 ROS 包改动也要重建 |

## 5. 排查顺序（别一上来就问人）

1. **报错信息** → 先看 `README.md` 的「一定会踩的坑」与 `knowledge/docs/progress.md` 的坑表（都是"不报错但结果不对"类的实录）；
2. **数字不对** → `knowledge/docs/位姿估计.md`（距离/倾角口径）、`knowledge/docs/相机标定.md`（内参、RMS 门槛）；
3. **结构该放哪** → 第 2 条的依赖方向 + `vision/docs/interface.md`（类型与接口的唯一来源）；
4. **还没解决** → 把"命令 + 完整输出 + 期望数字"三样一起问，比"跑不起来"快十倍。
