# 视觉与整机联调说明

> 基线：2026-11-02，当前第一版为 YOLO + 同步 RGB-D 可见平面候选。正式字段以 [接口契约](../../vision/docs/interface.md#rgb-d-可见平面候选输出2026-11-02) 和实际代码为准；新话题或语义进入整机集成前按团队规范评审。

## 1. 视觉交付什么

相机彩色与对齐深度图按采集时间配对，YOLO 检测后，对每个框分别拟合平面。满足选面条件的候选输出可见平面内点重心和法向。当前有两个独立话题：

| 话题 | 类型 | 用途 |
|---|---|---|
| `/rgbd_side/candidates` | `vision_msgs/msg/Detection3DArray` | 给其他节点读取位置、方向、类别与置信度 |
| `/rgbd_side/markers` | `visualization_msgs/msg/MarkerArray` | RViz 中的重心、法向箭头与文字 |

每个 `Detection3D` 的 `results[0]` 对应当前一帧中一个候选：

- `pose.pose.position` 是**可见平面内点重心**，单位米；不是完整物体中心或吸附点。
- `pose.pose.orientation` 的局部 +Z 指向朝相机的单位法向。绕法向的转角是构造值，不是实测 yaw 或完整物体姿态。法向不合格时该候选不发布。
- `hypothesis.class_id` 是模型类名，`score` 是 YOLO 置信度，不是深度质量或抓取成功率。`id` 留空，没有跨帧身份。
- bbox 中心复用重心，方向是单位占位、尺寸为零；协方差未估计。不要将这些占位值解释为零误差或真实物体尺寸。
- 数组与候选 header 是配对**深度图采集时间**及其光学 `frame_id`。光学系 X 向右、Y 向下、Z 向前；Z 是光轴分量，不是斜距。这里不做 TF，也不把光学坐标重命名为机械臂基座坐标。

接收端可用四元数 `(x,y,z,w)` 计算光学系单位法向：

```text
nx = 2 * (x*z + w*y)
ny = 2 * (y*z - w*x)
nz = 1 - 2 * (x*x + y*y)
```

当前接口没有逐框的完整失败原因或可靠跟踪 ID。空数组可能来自无目标、无有效选面或撤销，不能据此推断具体原因；窗口、快照和运行摘要用于诊断。候选消息和标记都是 Reliable、Volatile、KeepLast(1)。默认图对按较早的本地接收时间计算 500 ms 有效期；无目标、过期、几何重置或处理错误时按现有策略发布空数组及清除标记。撤销沿用最后一次 header；接收方必须自己处理消息时效、空数组和发布节点断流，不能无限复用旧值。

## 2. 环境与准备

- 已验证过的环境：ROS 2 Jazzy、Orbbec ROS wrapper/SDK 2.9.3、同一解释器可导入 `rclpy`、项目 `vision`、NumPy 和 OpenCV ≥4.10。`pyproject.toml` 是 Python 依赖来源；[深度 README](../../vision/depth/README.md#环境与启动) 给出环境准备示例。
- 准备 Gemini 336L 和 USB 3 连接，关闭其他占用相机的程序。示例工作区路径均从仓库根目录执行。
- 从模型维护者处取得配套 `knowledge/models/yolov8n_mix4.onnx` 和 `yolov8n_mix4.names.json`。权重与类名表被 Git 忽略，不随 clone 分发；默认 640 输入、0=block、1=top。默认是 OpenCV DNN 的 CPU 推理，GPU 透传不会自动加速。本次本机文件 SHA-256：ONNX `f5f43f20445efac80da541806424240aadc6b1c2ab13042d4660e31ca3814794`；类名表 `81b473df621397bd67d4e2fe880dd0234d43cd42cc84443f4ddc873caee3621c`。使用不同版本时记录其来源与 hash。
- 彩色与对齐深度的 `CameraInfo` 由实际驱动按分辨率提供；不要硬编码历史内参或把另一台设备的标定文件直接套用。当前算法只接受配套尺寸/frame、彩色 plumb_bob 与对齐深度零畸变网格；D2C 空间准确度仍需现场验证。
- 相机采集参数在 `ros2_ws/src/vision_depth/config/rgbd_capture.yaml`，默认 848×480@30、同步、SW D2C 到彩色、深度换算为毫米；查看器参数在 `config/rgbd_side_viewer.yaml`。默认软件降噪开启，空间、时间滤波关闭；不要将现场临时启用的补洞当成默认配置或直接测量值。

## 3. 同机启动与观察

以下以本机 `~/.venvs/up70-rgbd` 为例；新环境需按 [深度 README](../../vision/depth/README.md#环境与启动) 自行准备，而不是假设此路径随仓库分发：

```bash
# 终端 A：仓库根目录
source /opt/ros/jazzy/setup.bash
source ~/.venvs/up70-rgbd/bin/activate
cd ros2_ws
python -m colcon build --packages-select vision_depth --symlink-install
source install/setup.bash
cd ..
export ROS_DOMAIN_ID=97
ros2 launch vision_depth rgbd_side_viewer.launch.py rviz:=true
```

另开终端时同样从仓库根目录加载 ROS、Python 虚拟环境和 `ros2_ws/install/setup.bash`，然后使用与启动端相同的 domain 和 DDS 配置：

```bash
export ROS_DOMAIN_ID=97
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export FASTRTPS_DEFAULT_PROFILES_FILE=$PWD/ros2_ws/src/vision_depth/config/fastdds_shm_only.xml
ros2 topic echo /rgbd_side/candidates
# 另开终端可查看发布频率和标记
ros2 topic hz /rgbd_side/candidates
ros2 topic echo /rgbd_side/markers
```

RViz 默认 Fixed Frame 为 `camera_color_optical_frame`，实际输入不同则改成深度图 frame。黄色点是重心，青色箭头为朝相机法向，箭头长度固定 0.10 m 仅供显示。窗口按 Q/Esc 退出、S 保存诊断快照、D 切换深度图；快照不是人工真值。需要复用已有对齐相机或 bag 时传 `start_camera:=false`；确保四路图像/CameraInfo 实际满足输入要求。

### 部署拓扑限制

当前实时 launch 显式设置 Fast DDS 仅共享内存配置，**只能用于同机通信**；设置相同 `ROS_DOMAIN_ID` 不会让其他电脑直接接收到这些话题。不要把 SHM 配置永久写入通用 shell 环境。机械臂、底盘和视觉的机器划分尚未确定；跨机网络传输、发现、QoS、时间同步和大图带宽须在部署拓扑明确后单独设计并验证，不能简单去掉 SHM 就宣称可用。

## 4. 当前验收边界与待联调

- 候选选出的可能是顶面、侧面或误选平面，叠放箱子可能被一个框合并；法向不能单独证明选面对或可以抓取。当前未实现顶面分类或吸附点规划。
- 彩深时间配对、回放和话题传递已有测试；空间对齐、绝对定位与法向角度精度仍为 UNVERIFIED。补洞值包含估计，不能当作真实深度精度提升。
- 既有真机监听出现过长时间结果间隔和几何重置，连续稳定性未通过；详见 [深度进度](../../vision/depth/docs/progress.md)。后续在现场记录输入频率、结果年龄、丢帧、过期、重置和断连恢复。
- 机械臂侧需和视觉组明确目标定义、有效状态、停止策略、相机到基座的手眼标定/TF、工具接近轴与坐标单位；底盘运动引入的时间和坐标变换另行约定。没有这些约定和独立测量，不把候选当作动作指令。
- 同一项目的海康/ArUco/HSV 链路和离线工具继续保留；数据、模型权重与本地 `output/` 不随 Git 分发。具体入口见 [文档索引](README.md)。
