# data 目录说明

数据集与回放素材的落脚点。**本目录内容不进版本库**（图片和视频动辄几百 MB，进库会让 clone 时间失控），只有这份说明会被提交。

---

## 子目录约定

```
data/
├── clips/        影像片段（图片或视频），用于回放调试
├── raw/          原始采集，未做任何处理
├── labeled/      标注完成的成品，供 YOLO 训练用
└── synth/        合成图输出（如果需要从合成图造数据）
```

上图这几个目录在仓库里并不存在——需要时自己建，`.gitignore` 已经配好忽略规则。

---

## 命名规则

建议带上采集条件，因为**光照是判色任务的头号变量**，之后回看时能不能区分采集环境，决定了这批数据还有没有用。

```
clips/
├── 2026-10-20_白天_室内灯_A机位_红蓝块.mp4
├── 2026-10-20_白天_室内灯_B机位_红蓝块.mp4
└── 2026-10-21_夜晚_射灯_近距离_三色.mp4
```

至少包含：日期、光照条件、机位或距离、内容。

---

## 采集时要注意的四件事

这四条都直接影响判色能不能调出来，不是"顺手做一下"的建议。

1. **锁死曝光与白平衡**。自动模式下拍出来的素材，颜色分布会随镜头移动而变化，阈值无法收敛。
2. **同时拍几张"空场景"**。没有目标只有场地背景的图，用来确认阈值不会把背景误判成目标。
3. **覆盖光照的边界情况**。射灯直射、逆光、阴影里各拍一段。只有顺光素材的话，编出来的阈值一到现场就废。
4. **记下相机型号与参数**。分辨率、帧率、曝光值、白平衡值。换相机后这些都要重来，不记下来就得从零试。

## 与算法开发的关系

有素材之前，用合成图开发算法（`python -m vision run --set input.source=synthetic`）——合成图的颜色、位置、噪声完全可控，比真实数据更适合定位算法 bug。

有素材之后，用回放验证（回放源已实现，读图片目录或视频文件）：

```bash
python -m vision run --set input.source=replay \
  --set input.replay.path=data/clips
```

回放的价值是**可重复**：同一段视频跑两遍结果必须逐帧一致，才谈得上对比两次调参的效果。直接接摄像头做不到这一点。
