## 待办任务

### 1. 收尾本轮程序

- [ ] 补跑 RGB-D、深度报告、架构及深度模块回归，重新构建 `vision_depth`；记录最终结果。
- [ ] 检查本轮未提交改动和 `raw_021` 元数据，核对测试报告、文档与代码一致。
- [ ] 更新进度文档及验收修正说明：记录 `raw_021` 已采集、采集完整性和时间配对通过；修正“尚未新录真机包”等过时描述。
- [ ] 按仓库协作流程审阅并提交本轮改动。

### 2. 核清彩色与深度的像素网格

- [ ] 确定彩色图和 SW D2C 深度进入同一像素网格的可用路径，核对实际图像、配套 CameraInfo、畸变状态和光学坐标系。
- [ ] 核实对齐深度的 Z 定义与反投影方式，记录驱动版本、参数和依据。
- [ ] 用实际输出验证共同网格；证据不完整时，空间对齐继续标记 `UNVERIFIED`。
- [ ] 冻结采集配置：848×480@30、仅 SHM、10 ms 配对容差；若配置变化，重做受影响的验证。

### 3. 补采三场景并验收空间对齐

- [ ] 固定相机，准备箱子、卷尺和较大的哑光背景；确认两条非平行边的两侧均有可辨认的有效深度。
- [ ] 分别采集中心近、中心远、右侧中距离三个场景；每段录 3 秒预热和至少 10 秒稳定段。
- [ ] 每段记录卷尺实测距离、测量基准、物体尺寸和摆放条件；未知值保持空缺。
- [ ] 每个场景点选两条非平行的对应实物边，共六条，并逐张复查是否存在明显张开或整体错位。
- [ ] 六条边均可测、中点偏移均 ≤5 px、人工复查通过，才将本轮空间冒烟检查记为 `PASS`；不可测保留原因。
- [ ] 如需遮挡诊断，另采两个箱子前后错开的样本；它不能代替上述三个场景。

### 4. 补齐连续与运动验证

- [ ] 补录完整 120 秒稳定段，检查双流时间覆盖、帧率、接收间隔和每 10 秒趋势。
- [ ] 检查已有运动包 `raw_018` 中运动时彩色与深度的实际画面对应关系；仅凭 header 配对不能证明曝光同步。
- [ ] 必要时补录运动样本并记录运动速度或可估计的图像速度。

### 5. 评估抓取定位

- [ ] 调整机位，使箱子顶面和支撑平面清楚可见；确认 ROI 没有裁掉需要检测的区域。
- [ ] 完成 RGB-D 空间验收后，先用人工框验证与深度的融合，再评估候选数量、中心重复性和法向。
- [ ] 准备独立位置参考，记录测量基准及不确定度，评估真实位置误差；相对位移验证不能代替相机系绝对位置验收。
- [ ] 根据失败样本决定是否修改顶面提取、候选筛选或时序处理，并区分调参与验收数据。
