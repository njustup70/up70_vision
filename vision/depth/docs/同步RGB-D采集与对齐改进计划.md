# 同步 RGB-D 采集与对齐改进计划

> 日期：2026-10-27
> 类型：活文档，待实施计划；下述工具、阈值和实测交付物尚未完成。
> 上位方案：[深度相机识别改进方案](深度相机识别改进方案.md)第 5.1、5.2 和第九节阶段 2。
> 设备：Orbbec Gemini 336L；不依赖 YOLO 权重。
> 修订：首轮空间检查采用本地点击标注，收敛为三场景冒烟测试；本文仍是计划，不表示代码或现场验收已完成。

## 1. 本阶段目标

把同一次采集的彩色图和深度图可靠地配成一对，并验证：彩色图中箱子的像素区域能够对应到正确的深度区域，离线回放能复现这一对应关系。

交付给下一阶段的是：**已验证的图像话题、时间戳配对规则、对齐深度与配套相机几何信息，以及一套可以复算的真实 bag。**

本阶段暂不开发 YOLO 推理、箱子三维定位改进、手眼标定或机械臂动作。现有纯深度算法保留为原始深度基线；对齐深度在几何语义验证前，不直接接入现有抓取节点。

软件工具先开发和测试，再进行现场采集与验收。在线融合缓存和结果有效期属于下一阶段，本阶段不实现。

| 执行方 | 责任 |
|---|---|
| AI | 环境检查、代码与测试、启动相机、录包、保存参数、离线分析和报告 |
| 用户 | 连接并固定相机、测量箱子尺寸与距离、按场景摆箱、确认对应实物边界和排除区域 |
| 配合方式 | 每段采集前 AI 明确场景编号、摆放要求和稳定时长；用户确认准备完成后开始录制 |

分别记录软件交付、现场采集、时间同步、空间对齐的状态。软件交付可以独立完成；整项任务只有现场必测项全部通过才算完成。没有相机或人工标注时，继续完成不依赖它们的工作，相关验收保留 `UNVERIFIED`，不能以生成报告代替验收通过。

## 3. 实施顺序与通过条件

### 步骤 A：锁定环境、配置和数据语义

1. 在实际运行相机的环境中核对 ROS 发行版、驱动安装路径及版本、SDK/固件版本、相机序列号、USB 状态。
2. 首次使用设备默认档位探查可用模式；正式采集前冻结彩色和深度共同支持的同频档位，优先 30 fps，不支持时选择不超过 30 fps 的最高共同帧率，并记录原因。分辨率依据支持情况和带宽实测确定，请求值与实际值分别保存。
3. 保存启动命令、最终生效参数、话题类型和 QoS。分开记录请求档位与实际输出档位。
4. 确认彩色编码、深度编码和单位；记录图像尺寸、frame_id、K/D/R/P、畸变模型、校正状态以及外参/TF 的来源。
5. 明确同步使用的时间域。检查图像采集时间戳，不以消息接收时间或 bag 写入时间代替。
6. 为后续启动配置建立唯一参数来源：优先级为显式启动参数 > RGB-D 配置文件 > 声明的默认值。启动时保存请求值，录包时另存驱动实际生效值。纯深度和 RGB-D 模式分开命名，具体入口见第 7 节。

通过条件：能给出一份真实运行配置清单；未知字段明确标为未知，影响三维几何解释的未知项必须在步骤 D 前解决。先用 10 秒短包检查数据完整性，再录正式样本。

### 步骤 B：建立时间同步基线

采用分次启动对照，依次检查：

1. `raw`：同步关、D2C 关，记录原始双流基线。
2. `sync`：同步开、D2C 关，检查时间戳变化、频率和数据连续性。
3. `aligned`：同步开、D2C 开，作为融合输入候选模式，再次检查同步与频率。

每种模式先录稳定段 30 秒，另加预热 3 秒；启动稳定前的数据单列，不混进稳定段统计。模式切换后重新获取 CameraInfo，不复用上次配置的内参。

离线检查工具必须：

- 按图像 header 的整数纳秒时间戳配对；保存原始 sec/nanosec，避免浮点时间丢精度。
- 保留消息原始序号和 bag 时间；以原始顺序检查零值、重复和倒退，异常全部记入报告。零时间戳不参与配对，重复时间戳仅首帧参与；存在任一时间戳异常则完整性检查失败，排序不能掩盖异常。
- 合法帧按 header 时间、原始序号排序；以彩色为基准逐帧处理，在尚未使用且晚于上次匹配深度的候选中，选择容差内时间差最小的深度。等距选时间更早的深度，再按原始序号决定；每帧最多使用一次，不追求全局最大匹配数。
- 保存有符号时间差和绝对时间差，输出 P50、P95、最大值与直方图。
- 有符号时间差定义为 `depth_stamp_ns - color_stamp_ns`。分别以稳定段各路收到的全部图像帧为配对率分母，异常帧也计入；不静默跳过坏帧。
- 以最早选中图像的 bag 时间为起点排除前 3 秒预热；bag 时间只用于分段，正式配对使用 header 时间。两路必须完整覆盖声明的稳定时长，否则采集完整性检查失败。
- 另输出每个合法彩色帧不限制容差的最近深度时间差用于排错；该诊断允许复用候选，不计入正式配对和配对率。
- 统计实际频率与间隔分布。不能只通过彩色/深度帧数相等认定同步成功。
- 将配对容差写入报告；禁止为了提高配对率，自动扩大容差或复用同一帧。

初始工程门槛：在稳定段、双流同频配置下，两侧配对率均 ≥99%，配对容差固定为 10 ms；相机图像时间戳无零值、重复与倒退。成功配对的时间差 P95 只作描述统计：容差已限定为 10 ms，不能再把 P95 ≤10 ms 当成独立的同步通过证据。该门槛是本阶段提议，不是厂家精度承诺。30 fps 下帧周期约 33.3 ms，不能使用接近或超过一个帧周期的容差把相邻拍摄混为一对。

若同步时间戳存在固定偏移，先查驱动时间语义和采集参考时刻，报告偏移；不得未经依据直接改时间戳。静态时间统计通过后，还须用步骤 E 的运动场景检查实际画面对应关系；相同时间戳本身不能证明曝光完全同步。

### 步骤 C：启用 D2C，建立可核查的图像几何

1. 使用已安装官方驱动提供的对齐能力，明确目标为彩色坐标下的深度；先验证现有软件对齐模式。硬件模式仅在本机驱动和所选档位证实支持时比较。
2. 重新枚举实际发布话题，不预设对齐后一定新增话题，也不把话题名含有 `depth` 当作原始深度的证据。
3. 核对对齐深度的尺寸、采集时间戳、frame_id、配套 CameraInfo、畸变/校正状态，以及深度数值的 Z 轴定义。
4. 依据本机驱动/SDK实现或官方说明确定有效反投影模型。若消息与几何语义不一致，先调查驱动输出，不通过简单改 frame_id、复制彩色 K 或缩放图像补救。
5. 核查是否启用了补洞、空间/时间滤波等后处理。诊断数据尽量保留未补洞深度；若驱动在对齐时插值且没有原始有效性信息，记录限制，不能把非零像素都称为原始真实接触证据。

若原始深度和 D2C 深度不能同时输出，分次录制并明确模式。同步/对齐验证以同一段 bag 内的彩色和对齐深度为依据；两次录制不得冒充同次采集对照。

通过条件：报告可以明确回答“这张深度图如何从像素恢复三维点、三维点属于哪个光学系”，有对应图像和参数证据。结果三维精度留给后续独立实验验收。

### 步骤 D：静态像素对齐冒烟检查

**目的**：先查出 D2C 是否存在明显整体错位，以及近远和边缘是否异常，支持下一步框与深度融合开发。此次只做三场景人工参考检查，不承担精密标定、三维毫米精度或全工作区验收。开始前须确认同步与几何语义；缺少前置证据时为 `UNVERIFIED`。

#### D1. 三场景，各看一对图

相机固定，选不反光且边界清楚的箱子。采集中心近处、中心远处、右侧中距离三段，各稳定 10 秒，另加 3 秒预热，实际距离记入 meta。箱子完整位于共同视野内。

每段只取稳定段中点附近的一对有效 RGB-D 图：以稳定段起点的彩色 header 时间加 5 秒为目标，选彩色时间距其最近的有效配对，等距选较早帧。选中图不可测时保留原因，重新摆好重录，不悄悄挑成功帧。三场景合计 **3 对图，每对标两条非平行箱体边界，共 6 条边**。

原先的 15 条件矩阵、45 对图和每条件 36 点不作为本轮交付要求。冒烟通过后先推进融合；若发现距离或位置相关问题，再围绕失败条件加拍，不先扩成全量实验。

#### D2. 用本地 OpenCV 点击窗口产出坐标

在 `lab.rgbd_check` 中新增 `annotate OUT`：读取 `analyze` 已选出的图对，并排显示彩色和对齐深度伪彩。**不用网页，也不用人工填写 JSON 坐标。** 人在本机窗口点击，程序通过 OpenCV 鼠标回调取得坐标并保存。

每条边只做四次点击，窗口逐步提示：

1. 在彩色图中，沿一段清楚的箱体边界点击起点、终点。
2. 在深度图中，沿同一物理边界的对应中段点击起点、终点。
3. 程序画出两条线和测量位置；人检查选的是同一条实物边，按 `s` 确认保存。

再标一条方向不同的边，例如箱子的上边和右边。每对图共 8 次端点点击，三场景合计 24 次；无需逐个点击测量点。

窗口支持局部放大；显示坐标按 `原图坐标 = 显示坐标 / 显示比例 + 裁剪偏移` 还原，点击位置在左右面板中先扣除各自面板原点。JSON 只保存原图坐标，禁止把缩放窗口坐标直接当测量坐标。`r` 重选当前边，`u` 标为不可测并输入原因，`Esc` 保存已有记录后退出；未确认的边保持未验证。

彩色纹理（胶带、印字）不能代替深度边界；避开角点、遮挡带和空洞，选两张图都可辨认的同一条实物直边。两条线段覆盖相同的边界中段即可，端点无需恰好是同一个物理点。若只能看见空洞边缘，选 `u`，不要强行量一条线。

这是**人工确认的对应参考**，不是高精度标定真值；“不把自动边缘当真值”不禁止这种本地点选。第一版不需要自动边缘搜索、箱子多边形、排除多边形或手写法向。

#### D3. 每条边只报一个近似偏移

程序连接点击端点，取彩色线段中点，沿该线段法向求与深度线段的交点，以二者距离作为该边的近似像素偏移。交点须位于深度线段范围内；无唯一交点、越界或测量处没有可辨认深度边界时为 `UNVERIFIED`，不延长线段或补深度凑结果。

保存六条边各自的偏移和带线叠加图，足以查整体平移；同时由人查看线段两端是否明显张开，防止仅中点接近却存在旋转错位。小样本不计算 P50/P95，不统计所谓独立测量点数，也不宣称亚像素精度。

保留原始彩色、深度伪彩、有效深度掩码及带点击端点/线段/测量位置的局部叠加图。空洞等异常直接写在该边备注中；空洞导致有效边界后退不能直接归因为外参错误。第一轮不增加箱子区域覆盖率测量。

#### D4. 判定与交付

六条边均可测、近似偏移均 ≤5 px，且人工复查无明显张开或整体错位，记为本轮 `PASS`。5 px 只是待现场复核的冒烟排错门槛；如果点击位置模糊到足以影响门槛判定，局部放大后仍无法确认则标 `UNVERIFIED`，不硬判合格。超过门槛为 `FAIL`，保留图并查因。

交付只要求：**3 对原图、6 条人工确认边界的 JSON、6 行偏移结果、3 组标注叠加图及异常备注**。结论限定为“通过三场景静态对齐冒烟检查，可以继续融合开发”；全工作区和毫米精度尚未验收。步骤 E 的运动与连续录制仍分别检查。

### 步骤 E：检查运动、录制和回放

1. 相机固定，缓慢横向移动箱子，再移出、移入画面，记录约 20 秒，检查运动时彩色轮廓与深度边界是否分离。
2. 对同一 bag 直接离线分析，再做 ROS 回放；核对配对帧索引、header、图像内容与 CameraInfo 一致。回放速度或 `/clock` 不得改写原始采集时间戳来掩盖配对问题。
3. 停止输入后，检查工具是否结束/报告缺流；后续在线配对器应使用有界缓存、超时丢弃和明确未匹配状态。缓存时长及结果有效期在融合阶段依据 YOLO 耗时和接收侧需求设定。
4. 增加完整配置下稳定段 120 秒连续录制，另加预热 3 秒，检查两路实际频率、间隔、配对率和资源占用是否随时间恶化。请求 30 fps 时，以双流各 ≥25 fps 为排错门槛；选择较低档位时，两路均须达到各自请求帧率的 90%，并记录档位。实际频率按稳定段帧数除以声明稳定时长计算，避免短暂突发掩盖后续停流。

运动测试先作逐帧人工检查；记录运动速度或可估计的图像速度，关联时间差和空间错位。后续按允许误差建立 `运动速度 × 时间差` 的容差预算，本阶段不凭空指定机械臂适用速度。

## 5. 记录与交付格式

bag 沿用 `raw_XXX` 递增命名，不覆盖旧数据。每段 bag 同存 `meta.yaml`，至少补齐：

- session、场景编号、物块编号与实测尺寸；箱子所在位置、相机固定情况、实际距离和测量基准。
- ROS/驱动/SDK/固件版本、设备序列号；启动命令与最终参数快照路径。
- 彩色/深度/内参实际话题、请求和实际档位、编码、深度单位、QoS。
- 同步开关、时间域、D2C 开关/模式/目标、原始与对齐图像的区别、后处理设置。
- 每路 frame_id、K/D/R/P、畸变模型及校正状态的证据；对应 CameraInfo 或配置快照路径。
- 量具、分度/不确定度；光轴倾角无法独立测量时填未知，机身水平仪读数单列。

新报告建议放 `output/rgbd/<session>/`，包含：

| 文件 | 内容 |
|---|---|
| `report.html` | 结论、配置、统计、静态/运动对照与失败样本 |
| `pairs.csv` | 两侧原始序号、整数时间戳、有符号时间差、匹配状态、导出图路径 |
| `unmatched.csv` | 未配对及异常帧、原因；完整保留统计分母 |
| `summary.json` | 版本/参数、配对规则/容差、频率/间隔、配对率、几何检查、逐条件空间统计及各项状态/原因 |
| `spatial_edges.csv` | 每段两行，三场景合计六行：场景、配对/边界编号、中点偏移 px、人工复查结论、状态和备注；不可测边也保留 |
| `overlays/` | 中心、边缘、各距离及运动样例的叠加与放大图 |
| `annotations.json` | 本地窗口生成的配对编号、原图尺寸、彩色/深度线段端点、人工确认状态及不可测原因；用于复算偏移 |

导出给 YOLO 侧的彩色图应保留原图分辨率、颜色约定和配对索引；训练缩放/补边留在模型输入处理环节。录包本体、图片和报告不入 Git，文本 meta 与可复现命令按仓库约定管理。

时间戳字段保存整数纳秒；缺值用 JSON `null` / CSV 空值，不用 0 冒充测量。状态统一为 `PASS / FAIL / UNVERIFIED / SKIP`，每项附原因：缺输入或证据为 `UNVERIFIED`，已测不达标为 `FAIL`，确实不适用为 `SKIP`。`raw`/`sync` 模式的空间对齐检查可为 `SKIP`；`aligned` 缺标注只能为 `UNVERIFIED`。阶段总体通过要求所有必测项为 `PASS`，不能用 `SKIP` 跳过必测项。

## 6. 工作拆分与阶段出口

1. **第一轮：环境清单 + 10 秒短包。** 先确认双流、内参和单位，避免批量采错。
2. **第二轮：同步对照 + 最小检查工具。** 三种模式各约 30 秒，输出配对索引和时间差报告。
3. **第三轮：D2C 三场景冒烟。** 中心近处、中心远处、右侧中距离，各取一对图、本地点击两条边，完成六条偏移和叠加检查。
4. **第四轮：运动 + 连续录制。** 完成步骤 E，生成报告和失败样例，冻结可复用配置。仅在定位具体问题时增加相应静态场景，不默认扩展完整矩阵。

每轮检查通过再扩大采集；驱动参数/档位变化后重做相关同步与对齐检查。软件工具可以先开发，硬件结论必须来自现场数据。

本阶段完成时应能交付以下五项：

- 一条可复制的相机启动命令及对应最终参数快照。
- 一套完整记录的同步 RGB-D bag，彩色/深度/配套内参齐全。
- 一份时间同步统计和确定的配对规则。
- 一份含三场景图对、六条边的点选标注、六行偏移和叠加图的冒烟报告，运动/连续录制单列；各门槛明确 `PASS / FAIL / UNVERIFIED / SKIP`，结论不扩展为全工作区精度通过。
- 一份给 YOLO 侧的图像来源、原图尺寸/颜色、采集时间戳和未来检测消息对接说明。若变更共享话题或接口，登记到 `vision/docs/interface.md`，按协作规范评审后合并。

这五项齐备后，再进入“人工框/YOLO 框 + 对齐深度”的融合开发。

## 7. AI 执行约定与拟新增入口

**以下命令和模板描述待实现能力，不表示现在可以运行。** 本次修订只更新计划书；实施软件时才新增相关文件和入口。

### 7.1 环境、配置与采集入口

相机采集使用本机 Jazzy，保留原纯深度启动入口。新增 `rgbd_capture.launch.py` 和配套 RGB-D YAML；该 launch 根据 `mode:=raw|sync|aligned` 设置同步/D2C，模式默认 `aligned`。点云关闭，深度毫米缩放开启，D2C 为软件对齐至彩色，时间域默认 `global`，其余驱动后处理逐项记录。显式给出的底层参数若与模式冲突则报错，不静默覆盖模式。

新增 `ros2 run vision_depth rgbd_capture` 录包入口，必填参数为 `output_dir`、`duration_s`、`session_config`；`warmup_s` 默认 3。配置文件包含场景、模式、相机节点名和明确的四路图像/内参映射。输出目录存在时拒绝覆盖，不自动删除或复用已有 bag。

先检查两路图像与对应 CameraInfo，保存驱动实际参数、发布端 QoS 和图像几何快照，再调用 ROS bag。录制总时长为 `warmup_s + duration_s`；依据发布端 QoS 生成录包覆盖配置。正常结束发送 SIGINT 等待 bag 完整关闭，异常保留日志和未完成状态。存在相关 TF 时一并录制；动态 TF 与静态 TF 的录制 QoS分别按实际发布端核对。

自动话题发现只在每种角色有唯一候选且语义明确时填入映射；存在多个候选时列出名称、类型、frame 和尺寸，等待明确选择，不猜测哪个话题为原始/对齐深度。驱动在对齐后复用原话题时以配置和几何证据区分。

实施后在仓库根执行环境准备，再在 `ros2_ws` 构建；首次缺依赖须先检查现有 Python 环境，避免混装导致 ROS 依赖不可见。说明书须补上实际使用的 Python 解释器和依赖安装方法。

```bash
source /opt/ros/jazzy/setup.bash
cd ros2_ws
colcon build --packages-select vision_depth
source install/setup.bash
ros2 launch vision_depth rgbd_capture.launch.py mode:=aligned
```

另一终端加载相同 ROS 与工作空间环境后录包，例如：

```bash
ros2 run vision_depth rgbd_capture --ros-args \
  -p output_dir:=/absolute/path/bags/raw_XXX \
  -p duration_s:=10.0 \
  -p warmup_s:=3.0 \
  -p session_config:=/absolute/path/session.yaml
```

示例路径必须在现场替换为实际路径；`raw_XXX` 按当前目录下一可用编号确定，不覆盖旧记录。

### 7.2 离线入口与最小模板

离线入口固定为 `python -m lab.rgbd_check`，不依赖 ROS 运行时，不新建 `scripts/`，也不向 `vision/` 引入 `lab` 或 ROS 依赖。

```bash
python -m lab.rgbd_check inspect BAG
python -m lab.rgbd_check analyze BAG --out OUT
python -m lab.rgbd_check annotate OUT
```

`inspect` 输出候选话题、类型/数量、编码/尺寸、时间范围及内参摘要。`analyze` 默认读取 bag 同目录 `meta.yaml`，默认配对容差 10 ms，输出目录存在则拒绝覆盖；导出步骤 D 选中的一对图并在 `summary.json` 中记录配对编号和路径。没有标注时空间验收为 `UNVERIFIED`。

`annotate OUT` 读取该报告目录，在本机有图形显示的 Python 环境运行 OpenCV 窗口（不能使用 headless OpenCV）。用户按提示点选，工具保存 `annotations.json` 和带线图，并重新计算 `spatial_edges.csv`、更新本目录报告的空间部分；原始 bag 和图片不修改。重开时加载已有确认结果，重选覆盖前显示原线供人确认。没有图形显示时明确报告需在本机桌面运行，不退回要求用户手写像素 JSON。

采集 `session.yaml` 和 bag 内 `meta.yaml` 共享以下最小键；采集器补齐实际信息，不改写用户实测值：

```yaml
schema_version: 1
session: null
scene:
  condition_id: null
  position: null          # center / left / right / up / down；诊断场景单列
  distance_band: null     # near / mid / far
  measured_distance_mm: null
  distance_reference: null
  object_id: null
  object_size_mm: null    # [长, 宽, 高]，实测
  camera_fixed: null
  measurement_notes: null
capture:
  mode: aligned
  camera_node: null
  warmup_s: 3.0
  duration_s: 10.0
  complete: false
  topics:
    color: null
    depth: null
    color_info: null
    depth_info: null
  depth_unit: null
  time_domain: null
  requested_profile: null
  actual_profile: null
  geometry_evidence: null
  snapshots: null         # 版本、参数、QoS、K/D/R/P、frame 与校正状态的路径
```

标注最小结构为 `schema_version` 和 `frames`；每个 frame 记录 `condition_id`、`pair_id`、`image_size`、`edges`。每条 edge 只需 `edge_id`、`color_segment`、`depth_segment`、`confirmed`、`reason`；线段均为两个 `[x,y]` 原图浮点坐标，不可测时坐标可为 null 并填写原因。法向由程序根据端点计算，不要求人填写。配对编号、尺寸不一致或端点重合时拒绝该标注并给出原因，不能静默应用到另一幅图。

离线退出码：`0` 表示正常完成且已执行检查无失败，但仍可能有 `UNVERIFIED`；`1` 表示分析完成但有验收失败；`2` 表示参数、输入、依赖或运行错误，未完成分析。整项任务是否完成必须读取各项状态，不能只看退出码。

### 7.3 失败处理与人工交接

| 情况 | AI 的下一步 | 验收状态 |
|---|---|---|
| 没接相机或没有设备访问权限 | 保存检查结果，继续实现和测试离线工具，明确现场阻塞点，不反复尝试录空包 | 现场项 `UNVERIFIED` |
| 缺图像流、缺配套内参、录制提前终止 | 停止本段正式采集，保留日志/已有 bag，修复后使用新编号重录 | 已验证的采集完整性问题 `FAIL`，依赖项 `UNVERIFIED` |
| 档位不支持 | 重新探查共同档位，记录选择依据并冻结，重做受影响的同步/对齐检查 | 原尝试保留，不能冒称原档位通过 |
| 时间配对率或帧率不达标 | 分析异常帧、QoS、驱动与带宽，不自动扩大容差或降低门槛 | 对应检查 `FAIL` |
| D2C 几何语义不明 | 保存出处与疑点，停止空间验收和抓取接入，仍可生成诊断报告 | 空间项 `UNVERIFIED` |
| 缺标注、边界不可测或三场景未采齐 | 列出待补的场景/边界，提示本地窗口点选或重录，不增加测量点数凑验收 | 对应条件 `UNVERIFIED` |
| 已测空间偏移超门槛 | 保留全部失败样例并查因，修复后重采受影响条件 | 对应条件 `FAIL` |

## 8. 测试与软件/现场交付清单

软件测试动态生成小型 bag 与标注，不依赖外部大数据。至少覆盖：

- 时间配对：完全同步、容差内外和恰好边界、等距候选、不复用帧、零/重复/倒退时间戳、缺流、不同帧数、整数纳秒精度、预热分段与分母。
- 解码与几何：RGB/BGR、16 位深度、大小端、行 padding、错误数据长度、缺内参、图像尺寸或内参变化；变化时失败，不混合统计。
- 点选与空间测量：显示缩放/裁剪偏移/面板原点到原图坐标的换算，已知横向/斜向偏移，有限线段交点、越界、重合端点、标注错配，以及未确认/不可测状态。用少量合成样例验证，再人工走一遍四次点选、重选和保存，不用批量堆测量点。
- 采样与报告：稳定段中点抽样和平局规则、每段两条边、三场景合计六行结果、未采项保留、5 px 门槛和人工复查、状态与退出码。
- 可复现性：同一输入和参数生成相同配对索引、抽样、逐点测量和统计，报告运行时间等非测量字段除外。

实施时运行新增测试和已有深度/架构/报告回归测试，构建 ROS 包，核对三种模式的最终参数透传。文档本身的修订只需做格式、链接和要求一致性检查，不需要运行相机或测试待实现功能。

软件交付包含可构建代码、测试结果、配置及工具生成的标注示例、启动/录包/分析/点选命令和合成报告。现场交付包含真实 bag 清单、实际参数快照、三对静态图/六条人工确认边界及偏移、运动/连续录制结果，以及同一真实 bag 直接读取与 ROS 回放的 header、内容和配对一致性证据。

每次交接分别列出已完成、`FAIL` 和 `UNVERIFIED` 项。不能以“代码已提交”“工具运行成功”或“报告已生成”代替同步与空间对齐验收通过。
