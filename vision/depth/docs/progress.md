## 三、已完成

### 3.1 数据通路与噪声

- 相机：Orbbec Gemini 336L，深度 848×480 @30fps，Y16，`enable_depth_scale=true`，**全程毫米**。
- 噪声用「相机不动、移动平面」的方式测：逐像素沿时间轴求标准差，再对 ROI 内有效像素取中位数。
- 实测：

| 距离 | 噪声 σ | 4z² 估算 | 结论 |
|---|---|---|---|
| 663mm | 0.36mm | 1.76mm | 好于估算 |
| 1029mm | 0.60mm | 4.24mm | 好于估算 |
| 1605mm | 1.68mm | 10.30mm | 好于估算 |

- 拟合结果 `σ(z)=3.98e-6·z^1.74`，比计划书的 `4e-6·z²` 小 5~7 倍。合成数据用的是实测拟合，不是 4z²，否则噪声会偏大。
- 噪声数字只代表**重复性**，不代表绝对准确度；距离也是深度读数，没有用卷尺核对。

### 3.2 合成数据

- `lab/gen_synthetic_depth.py`：光线投射，输出 `depth.npy`（含噪声与无效值）、`clean_depth.npy`、`meta.json`、`preview.png`。
- 默认场景：相机高 600mm、倾角 25°、50mm 立方体；`--seed` 固定可复现。
- 五场景：`single`、`multi`、`edge`、`occluded`、`holes`，覆盖单目标、多目标、画面边缘、部分遮挡、表面空洞。
- 自检：顶面与桌面的深度差必须等于 `物块高 × cos(倾角)`。这条不过，后面的误差数字全部不可信。
- 量化到 1mm，与真实相机一致；不加量化会调出过度乐观的参数。

### 3.3 算法链路

`vision/depth/core.py` 五步：

1. ROI 裁剪（中心 0.6）→ 体素降采样（4mm）
2. RANSAC 找桌面（6mm、200 次）
3. 去掉桌面点，按深度跳变切连通域（18mm）
4. 每个簇取**离桌面最远的 20% 点**拟合顶面，SVD 取最小奇异向量当法向
5. 以顶面点云重心为吸附点，按五条判据算可吸性

关键实现：

- 顶面法向统一朝向相机，避免下游朝向时正时反。
- 顶面中心**直接返回重心**，不再做「投影回平面」。SVD 拟合前已减掉重心，平面本来就过重心，再减一次会把点沿法向挪 0~17mm。
- `top_size_mm` 用「过顶面中心的薄片（±3mm）+ 平面内二维跨度」算，不能拿相机系轴对齐包围盒代替。
- 可吸性五条取最小值：表面点数、平整度、倾角、空洞、簇点数。任何一条不达标，吸盘就漏气，不能用加权平均把短板平均掉。
- 返回空列表而不是抛异常：场景里本来就可能没有可吸目标；只有输入尺寸/内参不符才抛 `ValueError`。

### 3.4 ROS 外壳

- `fuse_node`：
  - 订阅 `/camera/depth/image_raw`、`/camera/depth/camera_info`
  - 发布 `/grasp_targets`（`vision_msgs/Detection3DArray`）、`/grasp_markers`（`MarkerArray`）
  - 输出 `output_frame=camera_link`；位置单位**米**
  - 参数：`depth_topic`、`info_topic`、`output_topic`、`marker_topic`、`output_frame`、`detect_every`、`min_score`、`use_2d_dets`
  - 深度 QoS 用 `best_effort`，避免回调堆积导致频率越来越低
- `fake_camera_node`：回放合成深度，真值单独发 `/ground_truth_targets`，不和检测结果混在一起。
- `depth_viewer`：看深度图。
- `launch/` 目前只有 `camera_only.launch.py`，**`fuse_node` 没有 launch/参数文件**，要手动 `ros2 run` 并传参。

### 3.5 测试

- `tests/test_depth.py`：7 个检查函数、18 条断言，覆盖类型校验、尺寸不符、单目标、多目标、空场景、小物块、空洞降分。
- `tests/test_architecture.py`：5 条，守住「`vision/` 不 import ROS、不 import `lab/`」。
- 仓库总测试数 121。
- 单独跑：`python tests/test_depth.py`（镜像里没有 pytest，每个文件都能直接执行）。

### 3.6 精度验证

**合成数据（M3）**

- 位置误差中位数：**3.86mm**（目标 <10mm）。
- 单目标吸附点与理论位置：<5mm。
- 150mm 场景五条检验：盒高 +0.1mm、倾角 +0.0°、尺寸 −6.2/−7.9mm。

**真机 raw_003**

- 顶面像素 10526px，洋红区域贴在盒子上沿；顶面法向与桌面夹角 **0.7°**；BEST 分数 1.00。这三项一起说明「取到的是顶面，不是正面」。
- 盒高误差：修 bug 前 +6.1mm，修后 **+2.4mm**（2mm 容差下仍差 0.4mm，这一条还没过）。
- 旧 `fit_top_face` 的问题：`centroid - ((centroid - top_pts[0]) @ normal) * normal` 的挪动量取决于数组顺序，真机实测 +3.9mm；合成数据每点残差接近 0，所以一直没暴露。
- 场景里背景杂物会产生多个背景簇（截图里 5 个，分数都是 0.00），只有盒子是 1.00。**数目标不能数簇数，要数分数 >0 的可吸候选。**

## 四、未完成与下一步

### 4.1 最优先：真机顶面中心精度（M2）

现状的五个检验里，**没有一条直接验证顶面中心的 x/y**：

| 检验 | 量的东西 | 为什么不够 |
|---|---|---|
| 1 盒高 | 中心到桌面平面的距离 | 只验证 z |
| 2 倾角 | 桌面法向与光轴夹角 | 只验证安装角 |
| 3 尺寸 | 顶面平面内长宽 | 只验证尺度 |
| 4 顶面平行 | 顶面法向与桌面法向夹角 | 只验证面选对 |
| 5 检出 | 可吸候选数 | 不验证坐标 |

**下一步跑精度测试，建议按这个顺序：**

1. **补 `meta.yaml`**：盒高（直尺）、光轴倾角（手机水平仪）、物块长宽高、摆放位置、相机大致距离。没有 meta 的 bag 只能看链路，不能做精度。
2. **造 x/y 真值，优先用差分法**：
   - 桌面贴 50mm 网格，盒子中心放在网格交点上；
   - 每个位置录一段静止 bag，记录网格坐标；
   - 比较「相邻两次检测的位移」与「网格位移」——差分能绕开手眼外参，现阶段就能做；
   - 有 ArUco/棋盘格时，可把检测点投到桌面平面，直接比平面内坐标。
3. **指标与验收线**（与 `数据方案` 第八节一致）：
   - 位置误差：中位数 <15mm（真实数据）、P95 记录；
   - 法向误差：中位数 <5°；
   - 漏检率：<5%；
   - 单帧位置抖动：3σ 量级，记录最大轴 std；
   - 盒高、尺寸、倾角沿用现有五条检验。
4. **样本量**：至少 10 个位置 × 每个位置 3 次重复；每次静止 60 帧，用时间中位数和单帧各算一遍。
5. **场景矩阵**：理想、画面边缘、反光、遮挡、表面空洞、多目标。先做理想与边缘，再做反光/遮挡。
6. **记录模板**：bag + `meta.yaml` + `--json-out` + `--save-viz`，表里至少要有：位置编号、真值 x/y、检测 x/y、误差、法向角、分数、簇数、帧号。
7. **参数冻结**：测试前固定 `SuctionParams`，不要边测边调；调参用合成数据或单独的调试 bag。

### 4.2 其它缺口

- `raw_002`、`raw_003` 缺 `meta.yaml`；`raw_001` 是空场景没有物块。
- 真实失效模式没有系统记录：反光、透明、弱纹理、遮挡、贴画面边缘。
- `top_ratio=0.2` 是百分位取层：高盒子 + 大斜视时，侧面上沿也会落进同一层，顶面法向和中心会偏。合成与 raw_003 没暴露，不代表换场景不会。
- 返回的是「可见顶面点云重心」，不是完整顶面的几何中心。顶面缺一角（遮挡/丢深度）时中心会向另一侧偏，不会自动补几何中心。
- `fuse_node` 没有 launch/参数文件；`use_2d_dets` 的 YOLO 融合路径没有启用；真机整链 15Hz 预算没有实测记录。
- M4 正式安装、M5 手眼标定/基座系、D 机械臂联调、E 鲁棒性都还没开始。当前输出是相机系，不能直接给机械臂。
- 多目标只做了按分数排序，没有最优抓取顺序；节点里没有时序平滑/超时丢弃。

## 五、踩过的坑

> 每条都是「不报错但结果不对」的类型，比直接报错难查。改深度代码前先扫一遍。

| # | 现象 | 原因 | 处理 |
|---|---|---|---|
| 1 | 点云边缘整体外扩，中心附近正常 | 把 z 深度当成了欧氏距离 | 反投影用 `x=(u-cx)z/fx`、`y=(v-cy)z/fy`；只有画面正中心两者才相等 |
| 2 | 物块位置整体偏几厘米，怎么调参都不对 | ROI 裁剪后 `cx/cy` 没跟着平移 | 裁剪后重建 `Intrinsics`，`cx-x0`、`cy-y0` |
| 3 | 报「找不到桌面」 | RANSAC 阈值按米填了 0.006 | 阈值单位是毫米，默认 6.0 |
| 4 | 输出法向时正时反，下游预吸附位往桌子里退 | 平面法向 `n` 和 `-n` 都是合法解 | 统一朝相机；算夹角取绝对值 |
| 5 | 顶面拟合出斜平面，中心落进方块内部 | 拿整个簇拟合，簇里含多个面 | 只取离桌面最远的 20% 点 |
| 6 | 一个物块裂成几块，或物块和桌面粘成一片 | 深度跳变阈值太小/太大 | 经验 15~25mm，默认 18mm，要比噪声大一个量级 |
| 7 | 吸附点沿法向随机偏 0~17mm，盒高忽大忽小 | 把重心又「投影回平面」，减的是 `top_pts[0]` 的相对偏移 | SVD 平面本就过重心，直接返回重心；raw_003 曾因此 +3.9mm |
| 8 | 顶面尺寸总比直尺小几毫米 | 深度图边缘每边丢约 3px（驱动置零 + 跳变边界 + 连通域剔边） | 尺寸检验加 `2×3px×z/fx` 容差；不要因此改 fx |
| 9 | 用 `bbox_size_mm` 和直尺比，斜视时大很多 | 它是相机系轴对齐包围盒，混进了深度方向跨度 | 用顶面平面内的 `planar_extent` / `top_size_mm` |
| 10 | 包围盒偏大、中心偏向一侧 | 物块贴桌面一圈是混合像素，深度介于物体和桌面之间 | 顶面只取最高 20%，绕开这一圈 |
| 11 | 真实场景簇数远多于物块数 | 桌角、远处杂物都会成簇 | 只数分数 >0 的可吸候选；背景簇分数应为 0 |
| 12 | 单帧位置偶尔跳 3mm 以上 | 降采样、平面拟合、聚类都是非线性步骤 | 离线用时间中位数；中位数前必须剔除 0 值 |
| 13 | 1.6m 处墙面噪声算出来很大、平面残差 185mm | ROI 200px 在远处覆盖约 0.78m，混进了非墙物体 | 距离越远 ROI 越小；100px 后残差 5.2mm |
| 14 | bag 回放能跑，但没法算精度 | 只有 bag 没有 `meta.yaml` | bag 与 meta 必须同存；没有真值只能看链路 |
| 15 | 相机打不开，或节点频率越来越低 | 相机被 MVS 客户端占用；ROS 深度 QoS 用了 reliable | 相机独占，先关占用者；深度用 `best_effort` |
| 16 | 点云整体缩小/放大一千倍 | 深度单位 mm 与 m 混用 | Orbbec 16UC1 + `enable_depth_scale=true` 全程毫米；ROS 输出时才除 1000 |
| 17 | 顶面法向和中心在大斜视高盒上偏 | `top_ratio` 是百分位取层，侧面上沿混入 | 用 `--save-viz` 看洋红区域是否在顶面；必要时改薄片法（`select_slab`）而不是盲目调 20% |

## 六、复现命令速查

容器内运行，仓库根即容器里的工作目录；下面省略 `docker compose ... run --rm up70-vision` 前缀。

```bash
# 合成深度（单目标，默认 600mm / 25° / 50mm 方块）
python lab/gen_synthetic_depth.py --out data/syn/single_01

# 离线原型：B1-B5 全链路，打中间结果
python lab/proto_depth.py data/syn/single_01

# M3 误差评估（五个场景）
python lab/eval_accuracy.py data/syn/*

# A4 噪声实测
python lab/measure_noise.py bags/noise_050 bags/noise_100 bags/noise_200

# 真实 bag 五条检验 + 抖动 + 可视化
python lab/bag_detect.py bags/raw_003 --frames 60 \
  --truth-height-mm <直尺量> \
  --truth-size-mm <长> <宽> <高> \
  --truth-tilt-deg <水平仪读数> \
  --save-viz output/depth/raw_003_viz.png \
  --json-out output/depth/raw_003.json

# 单元测试
python tests/test_depth.py
python tests/test_architecture.py

# ROS：相机
ros2 launch vision_depth camera_only.launch.py
# ROS：检测节点（当前无 launch，手动传参）
ros2 run vision_depth fuse_node --ros-args -p min_score:=0.5 -p detect_every:=2
# ROS：假相机 + 真值
ros2 run vision_depth fake_camera_node --ros-args -p data_dir:=data/syn/single_01
```
